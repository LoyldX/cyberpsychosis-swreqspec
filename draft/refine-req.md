## 1. ขอบเขตที่ตัดออก (Out of Scope)

ตามคำสั่งปรับลดขอบเขตก่อนหน้า ได้ตัดรายการต่อไปนี้ออกจากระบบ:

1. **ระบบ POS และการขายสินค้าหน้าร้าน:**
   - เครื่อง POS และ Smart Counter Terminal
   - การบันทึกยอดขายเครื่องดื่มและสินค้าหน้าร้าน
   - การดึงยอดขายเครื่องดื่มไปแสดงผลบน BI Dashboard
2. **เครื่องสแกนเวลาและการเชื่อมต่อระบบ HR:**
   - เครื่องสแกนเวลาเข้า-ออกงานของพนักงาน
   - การซิงค์ข้อมูลเวลาทำงานเข้าสู่ระบบ HR
3. **ความปลอดภัยข้อมูลและมาตรฐานการเข้ารหัส (Data Privacy & Encryption):**
   - ข้อกำหนด `Data Privacy & Encryption: และข้อมูลส่วนบุคคลด้วยมาตรฐาน TLS 1.3/AES-256`
   - ข้อกำหนดทางกฎหมาย PDPA Compliance
4. **ฟังก์ชันคำนวณโภชนาการและสารอาหาร (Nutrition):**
   - ฟังก์ชันคำนวณสารอาหารและแคลอรีสำหรับสมาชิก (`FR-NUT-01`)
   - การเชื่อมต่อกับ Nutrition API ภายนอก (`IF-NUT-01`)

## 2. การจำแนกความต้องการที่อยู่ในขอบเขต (In-Scope Requirements)

> **หมายเหตุ:** รหัส ID ในเอกสารนี้เป็นการกำหนดขึ้นเพื่อใช้อ้างอิงชั่วคราวในการรีวิว (Candidate IDs) ตามเนื้อหาที่คงเหลือและเพิ่มเติมเข้ามา

### 2.1 Functional Requirements (FR) — ความต้องการทางฟังก์ชัน

| รหัสชั่วคราว | ความต้องการทางฟังก์ชัน (Functional Requirement) | คำอธิบายพฤติกรรมของระบบ |
|---|---|---|
| **FR-AUTH-01** | ระบบรักษา Session Login แบบ Persistent | รองรับการเข้าสู่ระบบของสมาชิกและรักษา Session ให้คงอยู่ด้วย Refresh Token เพื่อป้องกันปัญหาผู้ใช้ถูกบังคับออกจากระบบ (Auto-logout) บ่อยครั้ง |
| **FR-NOTI-01** | ระบบส่งการแจ้งเตือน (Push Notification) | ส่งข้อความแจ้งเตือนวันและเวลาเปิด-ปิดยิม รวมถึงข่าวสารประชาสัมพันธ์ไปยังแอปพลิเคชันของสมาชิก |
| **FR-LINE-01** | LINE Bot ดึงข้อมูลการจองคลาส | สมาชิกสามารถเรียกดูข้อมูลและสถานะการจองคลาสออกกำลังกายของตนเองผ่าน LINE Bot ได้โดยอัตโนมัติ |
| **FR-LINE-02** | LINE Bot ตอบคำถามเบื้องต้น (FAQ) | ระบบตอบกลับคำถามทั่วไปที่พบบ่อยเกี่ยวกับยิมและการใช้งานให้แก่ผู้ใช้ผ่าน LINE Bot อัตโนมัติ |
| **FR-ROST-01** | ระบบจัดการตารางงานเทรนเนอร์ (Trainer Roster) | เจ้าหน้าที่/ผู้จัดการสามารถจัด กำหนด และปรับปรุงตารางเวลาเข้างานและเวลาสอนของเทรนเนอร์แต่ละคนได้ |
| **FR-BKG-01** | ระบบจองคลาสออกกำลังกายออนไลน์ | สมาชิกสามารถเลือกและทำการจองคลาสออกกำลังกายที่เปิดรับผ่านระบบออนไลน์ได้ |
| **FR-BKG-02** | ระบบบล็อกคิวอัตโนมัติเมื่อเทรนเนอร์ไม่ว่าง | ระบบต้องตรวจสอบและบล็อกไม่ให้มีการจองคลาสซ้อนทันที ในกรณีที่เทรนเนอร์ติดสอนคลาสอื่นหรือไม่อยู่ในเวลาปฏิบัติงาน |
| **FR-INV-01** | ระบบจัดการรายการพัสดุและอุปกรณ์ (Inventory Catalog) | เจ้าหน้าที่สามารถเพิ่ม แก้ไข ลบ ค้นหา และตรวจสอบจำนวนคงเหลือของอุปกรณ์และพัสดุในยิมได้ |
| **FR-INV-02** | ระบบบันทึกการเบิกจ่ายและรับคืน (Stock Movement) | ระบบต้องบันทึกประวัติการเบิกใช้วัสดุสิ้นเปลือง การยืม-คืนอุปกรณ์ และการรับสินค้า/อุปกรณ์ใหม่เข้าสต็อก |
| **FR-INV-03** | ระบบแจ้งเตือนสต็อกขั้นต่ำ (Low Stock Alert) | ระบบต้องแจ้งเตือนเจ้าหน้าที่เมื่อจำนวนอุปกรณ์หรือของใช้ในคลังลดลงถึงจุดสั่งซื้อขั้นต่ำ (Reorder Point) |
| **FR-BI-01** | BI Dashboard แสดงจำนวนผู้ใช้บริการปัจจุบัน | ดึงข้อมูลการผ่านประตูทางเข้ายิม มาประมวลผลและแสดงจำนวนผู้เข้าใช้บริการที่อยู่ภายในยิมแบบทันที (Real-time Occupancy) |

### 2.2 Non-Functional Requirements (NFR) — คุณภาพและประสิทธิภาพของระบบ

| รหัสชั่วคราว | คุณลักษณะเชิงคุณภาพ (Quality Attribute) | ข้อกำหนด (Specification) |
|---|---|---|
| **NFR-SEC-01** | Network Segmentation (VLAN) | แยกวงเครือข่าย Wi-Fi ออกจากกันอย่างเด็ดขาด (เครือข่ายสำหรับพนักงาน และ Wi-Fi สมาชิกทั่วไป) เพื่อความปลอดภัยของระบบภายใน |
| **NFR-PERF-01** | Real-time Booking Concurrency | การตรวจสอบสถานะคิวว่างและการบล็อกคิวเทรนเนอร์ต้องประมวลผลทันที เพื่อป้องกันปัญหาการจองซ้อน *(ต้องระบุ Latency ชัดเจน เช่น $\le$ 1 วินาที)* |
| **NFR-PERF-02** | Real-time Dashboard Refresh | การแสดงผลจำนวนผู้ใช้บริการบน BI Dashboard ต้องอัปเดตข้อมูลอัตโนมัติเมื่อมีการผ่านประตู *(ต้องระบุรอบเวลา เช่น ทุก 5–10 วินาที)* |
| **NFR-REL-01** | Session Persistence & Reliability | การจัดการ Session ผ่าน In-Memory Cache (Redis) ร่วมกับ Refresh Token ต้องมีอัตราการหลุดของ Session โดยไม่ตั้งใจไม่เกินเกณฑ์ที่กำหนด |
| **NFR-DATA-01** | Inventory Transaction Consistency | การตัดยอดหรือเพิ่มยอดสินค้าคงคลังต้องทำงานแบบ ACID Transaction เพื่อป้องกันปัญหายอดสต็อกผิดพลาดหรือติดลบจากการใช้งานพร้อมกัน |

### 2.3 Domain Requirements & Business Rules (DOM) — กฎเกณฑ์ทางธุรกิจ

| รหัสชั่วคราว | กฎทางธุรกิจ (Domain Rule) | รายละเอียดและเงื่อนไข |
|---|---|---|
| **DOM-BKG-01** | กฎการป้องกันคิวซ้อนของเทรนเนอร์ (Trainer Conflict Rule) | สมาชิกไม่สามารถจองคลาสกับเทรนเนอร์ในช่วงเวลาที่เทรนเนอร์มีคิวสอนอื่นอยู่แล้ว หรืออยู่นอกกะเวลาทำงาน (Off-shift) |
| **DOM-CAP-01** | กฎการคำนวณจำนวนผู้ใช้บริการในพื้นที่ (Gym Capacity Rule) | จำนวนผู้ใช้บริการที่แสดงบน Dashboard ต้องคำนวณจากการผ่านเข้า-ออกประตูจริง (ผ่านเข้า +1, ผ่านออก -1) เพื่อกำกับความจุของพื้นที่ |
| **DOM-INV-01** | กฎการเบิกจ่ายและยืมอุปกรณ์ (Equipment Checkout Rule) | การเบิกใช้วัสดุหรือยืมอุปกรณ์ต้องบันทึกชื่อผู้รับผิดชอบ วัตถุประสงค์ และวันที่กำหนดคืน (สำหรับอุปกรณ์ยืม) อย่างเคร่งครัด |
| **DOM-INV-02** | กฎเกณฑ์สต็อกปลอดภัย (Safety Stock Threshold) | อุปกรณ์และของใช้จำเป็นต้องมีระดับแจ้งเตือนขั้นต่ำ เพื่อไม่ให้อุปกรณ์ขาดแคลนจนกระทบการดำเนินงานของยิม |

### 2.4 Technical Constraints (CON) & External Interfaces (IF)

| รหัสชั่วคราว | ประเภท | รายการ | รายละเอียด |
|---|---|---|---|
| **CON-DB-01** | Constraint | Relational Database | กำหนดให้ใช้ PostgreSQL หรือ MySQL ในการจัดเก็บข้อมูลสมาชิก, ตารางงานเทรนเนอร์, ประวัติการจองคลาส และข้อมูลสินค้าคงคลัง (Inventory) |
| **CON-CACHE-01** | Constraint | In-Memory Database | กำหนดให้ใช้ Redis สำหรับบริหารจัดการ Session Login ของผู้ใช้ |
| **IF-GATE-01** | Interface | ประตูทางเข้ายิม (Turnstile Gate / Access Control) | เชื่อมต่อสัญญาณการผ่านเข้า-ออก เพื่อนำข้อมูลไปคำนวณจำนวนผู้ใช้บริการในยิม |
| **IF-LINE-01** | Interface | LINE Messaging API | เชื่อมต่อกับแพลตฟอร์ม LINE เพื่อให้บริการ LINE Bot และดึงข้อมูลการจอง |

## 3. รายงานการรีวิวและวิเคราะห์จุดบกพร่อง (Review Findings)

### 3.1 จุดที่ยังคงกำกวมหรือทดสอบไม่ได้ (Ambiguities & Untestable Points)

| ลำดับ | ข้อความเดิม | ปัญหาที่พบ | แนวทางแก้ไขที่แนะนำ |
|---|---|---|---|
| 1 | `...เพื่อแก้ปัญหา User 2 โดน Auto-logout บ่อย` | **คำศัพท์ไม่ชัดเจน ("User 2") และคำว่า "บ่อย" วัดผลไม่ได้** | ระบุประเภทผู้ใช้ให้ชัดเจน (เช่น สมาชิกทั่วไป หรือ เทรนเนอร์) และกำหนดอายุ Session/Inactivity Timeout เป็นตัวเลข เช่น คงอยู่ 30 วัน |
| 2 | `ระบบจองคลาสออนไลน์แบบ Real-time` | **คำว่า "Real-time" ไม่มีตัวเลขกำกับ** | กำหนด Response Time ของการตรวจสอบและบล็อกคิว (เช่น ภายใน 1–2 วินาที) |
| 3 | `BI Dashboard ... แสดงผลจำนวนผู้ใช้บริการแบบ Real-time` | **ไม่มีตัวเลข Refresh interval** | กำหนดความถี่ในการอัปเดตข้อมูลบนหน้าจอ (เช่น อัปเดตทันทีผ่าน WebSocket หรือ Polling ทุก 10 วินาที) |
| 4 | `PostgreSQL / MySQL` | **ยังไม่เลือก Database ชัดเจน** | ควรเลือกฐานข้อมูลตัวใดตัวหนึ่งเพื่อความชัดเจนในการกำหนด Architecture และ Library |
| 5 | `Inventory Management` | **ขอบเขตพัสดุในคลังยังไม่ระบุประเภท** | ระบุประเภทสิ่งของในคลังให้ชัดเจนว่าเน้น อุปกรณ์ยิม (Equipment), ของใช้สิ้นเปลือง (Supplies) หรือ สินค้า |

### 3.2 คำถามเปิดที่ต้องได้คำตอบจากทีม (Open Questions)

1. **Q1. ระบบจัดการสินค้าคงคลัง (Inventory Management) ครอบคลุมพัสดุประเภทใดบ้าง?**
   - *เกี่ยวกับ:* FR-INV-01, FR-INV-02, DOM-INV-01
   - *ถ้าไม่ตอบ จะต้องเดาว่า:* ครอบคลุมเฉพาะ "อุปกรณ์ออกกำลังกายสำหรับยืม-คืน" (เช่น เข็มขัดยกน้ำหนัก, สายรัด) และ "ของใช้สิ้นเปลืองของยิม" (เช่น ผ้าเช็ดตัว, สเปรย์ทำความสะอาด) โดยไม่ครอบคลุมสินค้าขายหน้าร้าน (เนื่องจากตัด POS ออกไปแล้ว)
   - *คนที่น่าจะตอบได้:* เจ้าหน้าที่ดูแลอุปกรณ์ยิม / Product Owner

2. **Q2. คำว่า "User 2" หมายถึงกลุ่มผู้ใช้ใด และต้องการให้อายุ Session (Login Persistence) คงอยู่นานเท่าใดก่อนต้องล็อกอินใหม่?**
   - *เกี่ยวกับ:* FR-AUTH-01, NFR-REL-01
   - *ถ้าไม่ตอบ จะต้องเดาว่า:* หมายถึงสมาชิกทั่วไปทุกคน และ Session มีอายุ 30 วัน
   - *คนที่น่าจะตอบได้:* ทีมพัฒนา Mobile App / Product Owner

3. **Q3. ประตูทางเข้ายิม (IF-GATE-01) มีการบันทึกทั้งขาเข้าและขาออกหรือไม่?**
   - *เกี่ยวกับ:* FR-BI-01, DOM-CAP-01, IF-GATE-01
   - *ถ้าไม่ตอบ จะต้องเดาว่า:* ประตูบันทึกทั้งขาเข้าและขาออก (เข้า +1, ออก -1)
   - *คนที่น่าจะตอบได้:* ฝ่ายอาคารสถานที่ / ผู้จัดการยิม

4. **Q4. สรุปจะเลือกใช้ PostgreSQL หรือ MySQL เป็นฐานข้อมูลหลัก?**
   - *เกี่ยวกับ:* CON-DB-01
   - *ถ้าไม่ตอบ จะต้องเดาว่า:* เลือกใช้ PostgreSQL
   - *คนที่น่าจะตอบได้:* Tech Lead ของทีม

5. **Q5. ผู้ใช้งานยืนยันตัวตนบน LINE Bot อย่างไรเพื่อเชื่อมโยงกับข้อมูลการจองคลาสของตนเอง?**
   - *เกี่ยวกับ:* FR-LINE-01, IF-LINE-01
   - *ถ้าไม่ตอบ จะต้องเดาว่า:* ผู้ใช้ต้องทำการผูกบัญชีด้วยเบอร์โทรศัพท์หรือ Webview ล็อกอินครั้งแรก
   - *คนที่น่าจะตอบได้:* ทีมพัฒนาระบบ
