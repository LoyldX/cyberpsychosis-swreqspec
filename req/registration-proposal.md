# ข้อเสนอ: ลงทะเบียนเข้าใช้ยิม (QR Code / ออนไลน์ล่วงหน้า)

> **สถานะ: ข้อเสนอ ยังไม่ได้รับการยืนยัน**
> ไฟล์นี้เก็บข้อเสนอจาก `req/refine-req.md` (v5) หัวข้อ 3, 4, 5, 6.2 ที่เป็น 🆕 Candidate
> ยังไม่ใช่ requirement ไม่มี ID ที่ยอมรับแล้ว ไม่มี spec, plan หรือ tasks และไม่อยู่ใน `specs/`
> จะย้ายเข้า `specs/` เป็น feature ใหม่ก็ต่อเมื่อทีมยืนยันและตอบคำถามด้านล่างแล้ว (ดู refine-req หัวข้อ 9.1)

## ที่มา

- Pain point ข้อ 1 (refine-req §1): ลงทะเบียนด้วยการเขียนลงกระดาษ ลืมปากกา และบางช่วงมีคิวยาว 7–8 คน
- Main Prior REQ ข้อ 1 (draft เดิม): ลงทะเบียนผ่าน QR Code หรือออนไลน์ล่วงหน้า

## คำถามที่เกี่ยวข้อง (ตาม refine-req หัวข้อ 8.2)

- **Q6** การลงทะเบียนต้องมีทั้ง QR Code และออนไลน์ล่วงหน้า หรือเลือกอย่างเดียว / ใครเป็นฝ่ายสแกน QR / ต้องลงทะเบียนทุกครั้งที่เข้าใช้หรือครั้งเดียว
  - ถ้าไม่ตอบ จะเดาว่า: ลงทะเบียนทุกครั้งที่เข้าใช้ โดยผู้ใช้สแกน QR ที่ติดไว้ที่จุดลงทะเบียนด้วยมือถือของตนเอง
  - คนที่น่าจะตอบได้: ผู้ดูแลยิม / Product Owner
- **Q7** ผู้ใช้บริการมีเฉพาะนักศึกษาหรือไม่ และผู้ใช้ที่ไม่มีรหัสนักศึกษา (เช่น บุคลากร บุคคลภายนอก) ลงทะเบียนอย่างไร
  - ถ้าไม่ตอบ จะเดาว่า: มีเฉพาะนักศึกษา
  - คนที่น่าจะตอบได้: ผู้ดูแลยิม
- **Q8** ข้อมูลลงทะเบียนเกี่ยวข้องกับการนับคนเข้ายิม (IF-GATE-01, FR-BI-01) และไฟล์ Excel เดิมหรือไม่
  - ถ้าไม่ตอบ จะเดาว่า: เป็นข้อมูลแยกกัน Dashboard ใช้ข้อมูลประตูอย่างเดียว
  - คนที่น่าจะตอบได้: ผู้จัดการยิม
- **Q11** เป้าหมายเวลาลงทะเบียนต่อคน และความยาวคิวสูงสุดที่ยอมรับได้คือเท่าใด
  - ถ้าไม่ตอบ จะเดาว่า: ไม่มีเกณฑ์ ทำให้ NFR-PERF-03 ทดสอบไม่ได้
  - คนที่น่าจะตอบได้: ผู้ดูแลยิม
- **Q12** "Main Prior REQ" หมายถึงลำดับความสำคัญสูงสุด (ต้องทำก่อน) หรือความต้องการเดิมก่อนออกแบบ Infrastructure
  - ถ้าไม่ตอบ จะเดาว่า: เป็นลำดับความสำคัญสูงสุด
  - คนที่น่าจะตอบได้: ทีม / อาจารย์ผู้สอน

## ข้อมูลที่เกี่ยวข้องกับ Constraint

- CON-DB-01 (ใช้ PostgreSQL หรือ MySQL เก็บข้อมูลลงทะเบียน) ใช้ได้ก็ต่อเมื่อ Q8 ตอบว่าข้อมูลลงทะเบียนอยู่ใน CON-DB-01 และชนิดฐานข้อมูลตอบ Q4 แล้ว

## หมายเหตุ

- ไม่มี AC และไม่มี task สำหรับข้อเสนอนี้ เพราะ AC ทั้งหมดถูกนำออกจาก spec จนกว่าทีมจะยืนยัน
- NS-1 และ NS-2 ใน refine-req หัวข้อ 2.3 ไม่ใช่ความต้องการของข้อเสนอนี้
