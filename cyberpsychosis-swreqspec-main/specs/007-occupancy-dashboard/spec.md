# Feature: Occupancy Dashboard
Spec ID: FR-BI-01, NFR-PERF-02, DOM-CAP-01, IF-GATE-01 | Source: `docs/srs/srs.md` (v5) | Status: Draft v1 | อัปเดต: 4 ตุลาคม 2569

## Goal
ระบบต้องแสดงจำนวนผู้ใช้บริการปัจจุบันภายในยิมจากข้อมูลการผ่านประตูจริง เพื่อแทนการนับด้วยมือและการบันทึกแบบ Excel และให้ผู้จัดการเห็นสถานะความแออัดของยิมได้แบบเรียลไทม์

## Scope
### In scope
- FR-BI-01 Dashboard แสดงจำนวนผู้ใช้บริการปัจจุบันจากข้อมูลการผ่านประตูทางเข้ายิม
- NFR-PERF-02 จำนวนบน Dashboard ต้องอัปเดตอัตโนมัติเมื่อมีการผ่านประตูหรือมีการเปลี่ยนแปลงสถานะผู้ใช้งาน
- DOM-CAP-01 การคำนวณจำนวนผู้ใช้บริการจากการผ่านเข้า (+1) และผ่านออก (-1)
- IF-GATE-01 เชื่อมต่อข้อมูลเหตุการณ์การผ่านเข้า-ออกจากประตูทางเข้ายิม
### Out of scope
- ตัดออกทั้งระบบ (refine-req §2.1–2.2): POS และการขายหน้าร้าน; เครื่องสแกนเวลาและการซิงค์ HR; Data Privacy & Encryption (TLS 1.3, AES-256, PDPA); Nutrition (FR-NUT-01, IF-NUT-01); ระบบเช็กสถานะเครื่องเล่นและคิวเครื่องเล่น (Q10)

## Constraints
- IF-GATE-01 ต้องรับหรือเชื่อมข้อมูลเหตุการณ์ทางเข้า-ออกจากประตูทางเข้ายิม (ประเภทสัญญาณและโปรโตคอลยังไม่ได้กำหนดชัดเจน)
- ระบบ Dashboard ต้องใช้อินพุตที่มาจากเหตุการณ์ผ่านประตูจริง ไม่ใช่ข้อมูลที่บันทึกด้วยตนเองจากไฟล์ Excel อย่างเดียว

| ID | กฎ |
|---|---|
| DOM-CAP-01 | **กฎคำนวณจำนวนผู้ใช้บริการในพื้นที่ (Gym Capacity Rule)**: จำนวนผู้ใช้บริการคำนวณจากเหตุการณ์ผ่านประตูจริง: ผ่านเข้า +1 และผ่านออก -1 ตามสถานะของเหตุการณ์ที่ได้รับ |

## Assumptions & Open Questions
- **Q3** ประตูทางเข้ายิม (IF-GATE-01) บันทึกทั้งขาเข้าและขาออกหรือไม่ (ยังไม่มีคำตอบ ค่าเดา: บันทึกทั้งสองทาง ผู้ตอบที่น่าจะได้: ฝ่ายอาคารสถานที่ / ผู้จัดการยิม) เกี่ยวกับ FR-BI-01, DOM-CAP-01, IF-GATE-01 — การบันทึกขาออกอยู่ในขอบเขต เพราะ DOM-CAP-01 กำหนดให้ผ่านออกลดจำนวนลง 1 จึงไม่ได้ตัดออก
- **Q8** ข้อมูลลงทะเบียนเกี่ยวข้องกับการนับคนเข้ายิมและไฟล์ Excel เดิมหรือไม่ (ยังไม่มีคำตอบ ค่าเดา: เป็นข้อมูลแยกกัน Dashboard ใช้ข้อมูลประตูอย่างเดียว ผู้ตอบที่น่าจะได้: ผู้จัดการยิม) เกี่ยวกับ FR-BI-01, DOM-CAP-01
- **Q10** ปัญหาเครื่องเล่นมีคนใช้อยู่เป็นประจำ (อาจเกี่ยวกับ FR-BI-01 ถ้าทีมเห็นว่าการรู้จำนวนคนช่วยได้) ยังไม่มีคำตอบ ค่าเดา: อยู่นอกขอบเขต
- ยังไม่มีหมายเลข Q: ระยะเวลาอัปเดตของ NFR-PERF-02 (refine-req §8.1 ข้อ 6 ระบุว่าไม่มีรอบเวลา)
- ยังไม่มีหมายเลข Q: รูปแบบสัญญาณและโปรโตคอลของ IF-GATE-01 (ไม่ได้ระบุใน refine-req)
- ยังไม่มีหมายเลข Q: การล็อกอินของผู้จัดการที่ดู Dashboard และสิทธิ์การดู (spec นี้ไม่ได้กำหนดการล็อกอินของเจ้าหน้าที่)
- คำถามข้อเสนอ UI (ไม่มี ID): จำนวนผู้ใช้บริการปัจจุบันควรเป็นข้อมูลหลักที่เห็นได้ทันทีเมื่อเปิด Dashboard ใช่หรือไม่? (ยังไม่มีหมายเลข Q)
- คำถามข้อเสนอ UI (ไม่มี ID): ตัวเลขควรอัปเดตเองโดยผู้ใช้ไม่ต้องกดรีเฟรชใช่หรือไม่? (ยังไม่มีหมายเลข Q เกี่ยวข้องกับรอบเวลาอัปเดต)
- หมายเหตุ: รอบ refresh ที่เป็นตัวเลขเป็นการตัดสินใจของทีม ไม่ได้กำหนดใน spec
