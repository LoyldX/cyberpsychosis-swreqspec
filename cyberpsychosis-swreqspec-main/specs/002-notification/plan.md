# แผน: Push Notification
Spec: `specs/002-notification/spec.md` (Draft v1) | สร้างเมื่อ 4 ตุลาคม 2569 | หน้านี้เป็นผลลัพธ์ที่ AI ร่าง คนตรวจต้องยืนยัน

## 1. สรุปแนวทาง
ระบบสร้างและส่ง push notification ไปยังแอปสมาชิกตาม FR-NOTI-01
ประเภทข้อความที่อยู่ในขอบเขตคือวันและเวลาเปิด-ปิดยิม และข่าวสารประชาสัมพันธ์
ผู้รับกลุ่มใด รอบเวลาการส่ง และความสัมพันธ์กับ Facebook Page ยังไม่ระบุ (Q9 และรายการที่ยังไม่มีหมายเลข Q)
จึงยังไม่กำหนดกฎการส่งที่ต้องทดสอบจริง และยังไม่เลือกบริการ push ให้ทีม

## 2. เทคโนโลยีที่ใช้
| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| บริการ push สำหรับแอปสมาชิก | ทีมเลือกเอง ไม่ได้มาจาก spec | ยังไม่ระบุ ทีมต้องเลือกก่อนพัฒนา |
| หลังบ้าน: Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นของรายวิชา |

## 3. โมเดลข้อมูล
| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Notification message | `message_content` (เนื้อหา), `category` (เปิด-ปิดยิม / ข่าวสาร), `member_id` (ผู้รับ), `send_status` (สถานะการส่ง) | FR-NOTI-01 |

- ฟิลด์เพิ่มเติม (เช่น ช่วงเวลาส่ง) ไม่สร้างเพราะ spec ไม่ระบุ
- ฟิลด์ `member_id` ขึ้นกับการตัดสินใจทีมเรื่องเจ้าของข้อมูลสมาชิก

## 7. ลำดับงาน
1. T-01 สร้างโครงข้อมูลข้อความแจ้งเตือน (รองรับ: FR-NOTI-01; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: เจ้าของข้อมูลสมาชิก (ผู้รับข้อความ))
2. T-02 สร้าง endpoint ส่งข้อความ (รองรับ: FR-NOTI-01; สถานะ: รอ Q9; รอการตัดสินใจทีม: ผู้รับกลุ่มและรอบเวลาส่ง; รอการตัดสินใจทีม: ผู้มีสิทธิ์สร้างข่าวสาร (การล็อกอินเจ้าหน้าที่))
3. T-03 เลือกและเชื่อมบริการ push (รองรับ: FR-NOTI-01; สถานะ: รอการตัดสินใจทีม: บริการ push สำหรับแอปสมาชิก (ทีมเลือกเอง ไม่ได้มาจาก spec))
4. T-04 ต่อการส่งกับแอปสมาชิกและทดสอบการถึงผู้รับ (รองรับ: FR-NOTI-01; สถานะ: รอ Q9; รอการตัดสินใจทีม: ผู้รับกลุ่มและรอบเวลาส่ง; รอการตัดสินใจทีม: อุปกรณ์และบัญชีสำหรับทดสอบ push)

## 8. สิ่งที่ยังไม่ทำ
- **Q9** Push Notification จะมาแทน Facebook Page หรือใช้คู่กัน และระบบต้องโพสต์ไป Facebook Page ด้วยหรือไม่
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (การโพสต์ไป Facebook, T-02, T-04)
- ยังไม่มีหมายเลข Q: ผู้รับกลุ่มใดและรอบเวลาส่ง ยังไม่สร้างจนกว่าทีมจะกำหนด (T-02, T-04)
- ยังไม่มีหมายเลข Q: บริการ push ที่ใช้ ยังไม่สร้าง T-03 จนกว่าทีมจะเลือก
- ยังไม่มีหมายเลข Q: ผู้มีสิทธิ์สร้างข่าวสาร (ต้องรู้บทบาทเจ้าหน้าที่ก่อน) ยังไม่สร้างสิทธิ์ใน T-02
