# แผน: LINE Bot
Spec: `specs/003-line-bot/spec.md` (Draft v1) | สร้างเมื่อ 4 ตุลาคม 2569 | หน้านี้เป็นผลลัพธ์ที่ AI ร่าง คนตรวจต้องยืนยัน

## 1. สรุปแนวทาง
ระบบรับและตอบข้อความผ่าน LINE Messaging API ตาม IF-LINE-01
สมาชิกเรียกดูข้อมูลและสถานะการจองของตนตาม FR-LINE-01 และระบบตอบคำถามที่พบบ่อยอัตโนมัติผ่านการตอบกลับของ webhook ตาม FR-LINE-02
การผูกบัญชี LINE กับสมาชิกยังไม่มีวิธีที่ตกลงกัน (Q5) จึงยังไม่สร้างการค้นข้อมูลการจองที่ผูกกับสมาชิกจริง
ข้อมูลการจองมาจาก 005 และจะยังไม่มีค่าจริงจนกว่า 005 มีข้อมูล
ไม่มีหน้าจอ FAQ บนเว็บ ตาม FR-LINE-02 ที่กำหนดให้ตอบคำถามที่พบบ่อยผ่าน LINE Bot

## 2. เทคโนโลยีที่ใช้
| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| LINE Messaging API | IF-LINE-01 | เป็น interface ที่ spec ระบุ |
| หลังบ้าน: Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นของรายวิชา |
| รูปแบบข้อความตอบ (Rich Menu / Flex Message) | ทีมเลือกเอง ไม่ได้มาจาก spec | ยังไม่กำหนดใน spec |

## 3. โมเดลข้อมูล
| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| LINE account link | `line_user_id` (ผู้ใช้ LINE), `member_id` (อ้างอิงสมาชิก), `link_status` (สถานะการผูก) | FR-LINE-01, IF-LINE-01 (ความสัมพันธ์รอ Q5) |
| Booking summary (อ่านจาก 005) | `member_id`, `booking_id`, `booking_status` | FR-LINE-01 |
| FAQ entry | `question_pattern` (รูปแบบคำถาม), `answer_content` (เนื้อหาคำตอบ) | FR-LINE-02 |

- ความสัมพันธ์ระหว่าง LINE account กับสมาชิกไม่สร้างจนกว่าจะตอบ Q5
- ฟิลด์ `member_id` ขึ้นกับการตัดสินใจทีมเรื่องเจ้าของข้อมูลสมาชิก

## 4. API / หน้าจอ
| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| POST `/line/webhook` | LINE event / ผลการตอบกลับ (รวมคำตอบ FAQ) | IF-LINE-01, FR-LINE-02 |
| GET `/line/bookings` | LINE identity ที่ผูกแล้ว (รอ Q5) / สถานะการจองของสมาชิก | FR-LINE-01 |

ไม่มี API หรือหน้าจอ FAQ บนเว็บ คำถามที่พบบ่อยส่งผ่าน webhook reply ตาม FR-LINE-02 เท่านั้น

## 5. ตารางตรวจ Constraints

## 7. ลำดับงาน
1. T-01 สร้างโครงข้อมูล FAQ entry (รองรับ: FR-LINE-02; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001))
2. T-02 สร้าง webhook รับและตอบข้อความผ่าน LINE Messaging API (รองรับ: IF-LINE-01, FR-LINE-02; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001))
3. T-03 ตอบ FAQ อัตโนมัติผ่าน webhook reply (รองรับ: FR-LINE-02, IF-LINE-01; สถานะ: รอการตัดสินใจทีม: ชุดคำถามที่พบบ่อยและวิธีจับคู่คำถาม)
4. T-04 ผูกบัญชี LINE กับสมาชิก (รองรับ: FR-LINE-01, IF-LINE-01; สถานะ: รอ Q5; รอการตัดสินใจทีม: เจ้าของข้อมูลสมาชิก)
5. T-05 ค้นข้อมูลการจองของสมาชิกที่ผูกแล้ว (รองรับ: FR-LINE-01, IF-LINE-01; สถานะ: รอ Q5)
6. T-06 สร้างรูปแบบคำตอบการจอง (รองรับ: FR-LINE-01; สถานะ: รอ Q5)
7. T-07 ต่อ LINE Bot กับ API จริงและทดสอบปลายทาง (รองรับ: IF-LINE-01, FR-LINE-01, FR-LINE-02; สถานะ: รอ Q5; รอการตัดสินใจทีม: บัญชี LINE ทดสอบ (test account); รอการตัดสินใจทีม: วิธีรัน Redis และฐานข้อมูลสำหรับ test)

## 8. สิ่งที่ยังไม่ทำ
- **Q5** ผู้ใช้งานยืนยันตัวตนบน LINE Bot อย่างไรเพื่อเชื่อมโยงกับข้อมูลการจองของตนเอง
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (ข้อ 3 LINE account link, ข้อ 4 GET `/line/bookings`, T-04, T-05, T-06, T-07)
- ยังไม่มีหมายเลข Q: พฤติกรรมเมื่อ LINE Messaging API ไม่ตอบสนอง ยังไม่สร้างจนกว่าทีมจะกำหนด
- ยังไม่มีหมายเลข Q: เจ้าของข้อมูลสมาชิก ยังไม่สร้างฟิลด์ `member_id` จนกว่าทีมจะตัดสิน (T-04)
- ยังไม่มีหมายเลข Q: ชุด FAQ ที่จะตอบ ยังไม่สร้างเนื้อหาคำตอบจนกว่าทีมจะกำหนด (T-03)
