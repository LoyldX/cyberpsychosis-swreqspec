# แผน: จัดการสินค้าคงคลังและอุปกรณ์
Spec: `specs/006-inventory/spec.md` (Draft v1) | สร้างเมื่อ 4 ตุลาคม 2569 | หน้านี้เป็นผลลัพธ์ที่ AI ร่าง คนตรวจต้องยืนยัน

## 1. สรุปแนวทาง
ระบบจัดการรายการอุปกรณ์และพัสดุ (เพิ่ม แก้ไข ลบ ค้นหา) ตาม FR-INV-01
บันทึกประวัติการเบิก ยืม-คืน และรับของเข้าสต็อกตาม FR-INV-02 พร้อมฟิลด์ผู้รับผิดชอบ วัตถุประสงค์ และวันกำหนดคืนตาม DOM-INV-01
การเพิ่มหรือตัดยอดอยู่ใน ACID transaction ตาม NFR-DATA-01 และแจ้งเตือนเมื่อถึง Reorder Point ตาม FR-INV-03 (รายการที่ DOM-INV-02 ครอบคลุมและการบังคับ reorder_point รอการตัดสินใจทีม)
ประเภทพัสดุรอ Q1 และชนิดฐานข้อมูลรอ Q4 จึงยังไม่กำหนดฟิลด์ประเภทและยังไม่เลือกเอนจินฐานข้อมูล
การบันทึกประวัติการเบิกไม่ต้องรอ Q1

## 2. เทคโนโลยีที่ใช้
| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| ฐานข้อมูลเชิงสัมพันธ์ (ACID) | CON-DB-01, NFR-DATA-01 | ยังไม่เลือก รอ Q4 (ค่าเดาคือ PostgreSQL) |
| หน้าบ้าน: React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้กับหน้าจอสต็อก (ข้อเสนอ ยังไม่ยืนยัน) |
| หลังบ้าน: Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นของรายวิชา |

## 3. โมเดลข้อมูล
| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Inventory item | `item_id` (รหัสรายการ), `quantity` (จำนวนคงเหลือ), `reorder_point` (จุดสั่งซื้อขั้นต่ำ, บังคับหรือไม่ รอการตัดสินใจทีม) | FR-INV-01, FR-INV-03, DOM-INV-02 |
| Stock movement | `movement_id`, `item_id`, `movement_type` (เบิก / ยืม / คืน / รับเข้า), `quantity` (จำนวนที่เคลื่อนไหว), `responsible_person` (ผู้รับผิดชอบ), `purpose` (วัตถุประสงค์), `due_date` (วันกำหนดคืน เฉพาะการยืม) | FR-INV-02, DOM-INV-01, NFR-DATA-01 |

- ฟิลด์ประเภทพัสดุ (item type) ยังไม่สร้างจนกว่าจะตอบ Q1
- ค่า `reorder_point` ของแต่ละรายการไม่ได้ระบุตัวเลขใน spec และการบังคับหรือไม่ รอการตัดสินใจทีม

## 4. API / หน้าจอ
| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| GET/POST/PUT/DELETE `/inventory/items` | ข้อมูลรายการ / ผลการจัดการรายการ | FR-INV-01 |
| POST `/inventory/movements` | ประเภท movement, จำนวน, ผู้รับผิดชอบ, วัตถุประสงค์, วันกำหนดคืน / ประวัติที่บันทึก | FR-INV-02, DOM-INV-01 |
| GET `/inventory/alerts` | จุดสั่งซื้อและยอดคงเหลือ / รายการแจ้งเตือน | FR-INV-03, DOM-INV-02 |
| หน้าจอรายการอุปกรณ์ (ข้อเสนอ ยังไม่ยืนยัน) | รายการ + ช่องค้นหา / แยกรายการถึง Reorder Point | FR-INV-01, FR-INV-03 |
| ฟอร์มเบิก/ยืม (ข้อเสนอ ยังไม่ยืนยัน) | ข้อมูลการเบิก / บันทึกหรือแจ้งข้อผิดพลาด | DOM-INV-01, FR-INV-02 |

- ยอดคงเหลือใหม่ของรายการถูกคำนวณและบันทึกภายใต้ transaction ตาม NFR-DATA-01 (ดู T-05) ไม่ใช่ส่วนของ API บันทึกประวัติ

## 5. ตารางตรวจ Constraints
| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |

| CON-DB-01 | Inventory item และ Stock movement (ข้อ 3) เก็บใน relational DB | ออกแบบแล้ว ชนิดฐานข้อมูลยังรอ Q4 |

## 7. ลำดับงาน
1. T-01 สร้างโมเดล item (รหัส จำนวนคงเหลือ) (รองรับ: FR-INV-01, CON-DB-01; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001))
2. T-02 เพิ่มฟิลด์ประเภทพัสดุ (item type) (รองรับ: FR-INV-01; สถานะ: รอ Q1)
3. T-03 CRUD และค้นหา item (รองรับ: FR-INV-01; สถานะ: รอการตัดสินใจทีม: การล็อกอินและสิทธิ์ของเจ้าหน้าที่/ผู้จัดการ (ใครแก้ไขรายการได้))
4. T-04 บันทึกประวัติ stock movement พร้อมฟิลด์บังคับ (รองรับ: FR-INV-02, DOM-INV-01; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ผ่าน T-01; ดูหมายเหตุ 001))
5. T-05 ACID transaction สำหรับการตัดและเพิ่มยอด (รองรับ: NFR-DATA-01; สถานะ: รอ Q4; รอการตัดสินใจทีม: วิธีรัน Redis และฐานข้อมูลสำหรับ test)
6. T-06 แจ้งเตือนเมื่อถึง Reorder Point (รองรับ: FR-INV-03, DOM-INV-02; สถานะ: รอการตัดสินใจทีม: รายการใดเป็นอุปกรณ์หรือของใช้จำเป็นตาม DOM-INV-02 และ reorder_point บังคับหรือไม่)
7. T-07 เชื่อม inventory กับฐานข้อมูลจริง (รองรับ: CON-DB-01; สถานะ: รอ Q4; รอการตัดสินใจทีม: วิธีรัน Redis และฐานข้อมูลสำหรับ test)
8. T-08 สร้างหน้ารายการอุปกรณ์ด้วยข้อมูลจำลอง (ช่องค้นหาและแยกรายการถึงจุดสั่งซื้อ) (รองรับ: FR-INV-01, FR-INV-03; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI รายการอุปกรณ์ (ดู Assumptions))
9. T-09 สร้างฟอร์มเบิก/ยืมด้วยข้อมูลจำลอง (รองรับ: DOM-INV-01, FR-INV-02; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI ฟอร์มเบิก/ยืม (ดู Assumptions))
10. T-10 ต่อหน้าจอกับ API จริงและทดสอบปลายทาง (รองรับ: FR-INV-01, FR-INV-02, FR-INV-03, DOM-INV-01, CON-DB-01; สถานะ: รอ Q1; รอ Q4; รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI ของสต็อก; รอการตัดสินใจทีม: การล็อกอินและสิทธิ์ของเจ้าหน้าที่/ผู้จัดการ)

## 8. สิ่งที่ยังไม่ทำ
- **Q1** Inventory ครอบคลุมพัสดุประเภทใดบ้าง
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (ฟิลด์ item type ใน T-02, การแสดงประเภทใน T-10)
- **Q4** เลือก PostgreSQL หรือ MySQL เป็นฐานข้อมูลหลัก
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (ACID transaction T-05, การเชื่อม DB จริง T-07, T-10)
- ยังไม่มีหมายเลข Q: ผู้ใช้ฝั่งเจ้าหน้าที่/ผู้จัดการล็อกอินอย่างไร และมีสิทธิ์ต่างกันหรือไม่ ยังไม่สร้างการตรวจสิทธิ์ใน T-03 จนกว่าทีมจะกำหนด
- ยังไม่มีหมายเลข Q: รายการจำเป็นตาม DOM-INV-02 และค่าระดับแจ้งเตือน ยังไม่สร้างการแจ้งเตือนสำหรับรายการที่ไม่ได้กำหนดว่าจำเป็น (T-06)
- ยังไม่มีหมายเลข Q: ข้อเสนอ UI ของสต็อก ยังไม่สร้างหน้าจอ (T-08, T-09, T-10)
