# Feature: จัดการสินค้าคงคลังและอุปกรณ์
Spec ID: FR-INV-01, FR-INV-02, FR-INV-03, NFR-DATA-01, DOM-INV-01, DOM-INV-02, CON-DB-01 (หลัก: FR-INV-01) | Source: `docs/srs/srs.md` (v5) | Status: Draft v1 | อัปเดต: 4 ตุลาคม 2569

## Goal
เจ้าหน้าที่จัดการรายการอุปกรณ์และพัสดุ ติดตามการเบิก ยืม-คืน และการรับของเข้าสต็อก และรับการแจ้งเตือนเมื่อจำนวนคงเหลือถึงจุดสั่งซื้อขั้นต่ำ (ขอบเขตนี้มาจาก FR-INV-01, FR-INV-02 และ FR-INV-03; pain point ใน refine-req §1 ไม่ได้กล่าวถึงสต็อกโดยตรง)

## Scope
### In scope
- FR-INV-01 เจ้าหน้าที่เพิ่ม แก้ไข ลบ ค้นหา และตรวจสอบจำนวนคงเหลือของอุปกรณ์และพัสดุ
- FR-INV-02 ระบบบันทึกประวัติการเบิกวัสดุสิ้นเปลือง การยืม-คืนอุปกรณ์ และการรับของใหม่เข้าสต็อก
- FR-INV-03 แจ้งเตือนเจ้าหน้าที่เมื่อจำนวนคงเหลือถึง Reorder Point
- NFR-DATA-01 การตัดยอดหรือเพิ่มยอดเป็น ACID transaction
- DOM-INV-01 การเบิกหรือยืมต้องบันทึกผู้รับผิดชอบ วัตถุประสงค์ และวันกำหนดคืนเมื่อเป็นการยืม
- DOM-INV-02 อุปกรณ์และของใช้จำเป็นต้องมีระดับแจ้งเตือนขั้นต่ำ
- CON-DB-01 ข้อมูลสินค้าคงคลังเก็บใน relational database (ชนิดยังไม่เลือก ดู Q4)
### Out of scope
- ตัดออกทั้งระบบ (refine-req §2.1–2.2): POS และการขายสินค้าหน้าร้าน; เครื่องสแกนเวลาและการซิงค์ HR; Data Privacy & Encryption (TLS 1.3, AES-256, PDPA); Nutrition (FR-NUT-01, IF-NUT-01); ระบบเช็กสถานะเครื่องเล่นและคิวเครื่องเล่น (Q10)

## Constraints
- CON-DB-01 ใช้ PostgreSQL หรือ MySQL จัดเก็บข้อมูลสินค้าคงคลัง (ยังไม่เลือก ดู Q4)

## Requirements (ยอมรับแล้ว)
| ID | ข้อกำหนด |
|---|---|
| FR-INV-01 | **จัดการรายการพัสดุและอุปกรณ์ (Inventory Catalog)**: เจ้าหน้าที่เพิ่ม แก้ไข ลบ ค้นหา และตรวจสอบจำนวนคงเหลือของอุปกรณ์และพัสดุได้ |
| FR-INV-02 | **บันทึกการเบิกจ่ายและรับคืน (Stock Movement)**: ระบบบันทึกประวัติการเบิกใช้วัสดุสิ้นเปลือง การยืม-คืนอุปกรณ์ และการรับของใหม่เข้าสต็อก |
| FR-INV-03 | **แจ้งเตือนสต็อกขั้นต่ำ (Low Stock Alert)**: ระบบแจ้งเตือนเจ้าหน้าที่เมื่อจำนวนคงเหลือลดลงถึงจุดสั่งซื้อขั้นต่ำ (Reorder Point) |

## Quality Requirements (ยอมรับแล้ว)
| ID | ข้อกำหนด |
|---|---|
| NFR-DATA-01 | Inventory Transaction Consistency: การตัดยอดหรือเพิ่มยอดสินค้าคงคลังต้องเป็น ACID Transaction เพื่อป้องกันยอดผิดหรือติดลบจากการใช้งานพร้อมกัน — เกณฑ์: ยอดคงเหลือไม่ติดลบ และไม่ผิดเมื่อมีการทำรายการพร้อมกัน |

## Domain Rules (ยอมรับแล้ว)
| ID | กฎ |
|---|---|
| DOM-INV-01 | **กฎการเบิกจ่ายและยืมอุปกรณ์**: การเบิกหรือยืมต้องบันทึกชื่อผู้รับผิดชอบ วัตถุประสงค์ และวันกำหนดคืน (เมื่อเป็นการยืม) |
| DOM-INV-02 | **กฎสต็อกปลอดภัย (Safety Stock Threshold)**: อุปกรณ์และของใช้จำเป็นต้องมีระดับแจ้งเตือนขั้นต่ำ |

## Assumptions & Open Questions
- **Q1** Inventory ครอบคลุมพัสดุประเภทใดบ้าง (ยังไม่มีคำตอบ ค่าเดา: เฉพาะอุปกรณ์ยืม-คืนและของใช้สิ้นเปลือง ไม่รวมสินค้าขาย เพราะตัด POS แล้ว ผู้ตอบที่น่าจะได้: เจ้าหน้าที่ดูแลอุปกรณ์ / Product Owner) เกี่ยวกับ FR-INV-01, FR-INV-02, DOM-INV-01 — ผลกระทบ: เฉพาะฟิลด์ประเภทพัสดุ (T-02) และหน้าจอที่ต้องแสดงประเภท
- **Q4** เลือก PostgreSQL หรือ MySQL (ยังไม่มีคำตอบ ค่าเดา: PostgreSQL ผู้ตอบที่น่าจะได้: Tech Lead) เกี่ยวกับ CON-DB-01 และ NFR-DATA-01
- ยังไม่มีหมายเลข Q: ผู้ใช้ฝั่งเจ้าหน้าที่/ผู้จัดการล็อกอินอย่างไร และมีสิทธิ์ต่างกันหรือไม่ (spec นี้ไม่ได้กำหนดการล็อกอินของเจ้าหน้าที่ จึงไม่สมมติว่ามีการล็อกอิน)
- ยังไม่มีหมายเลข Q: รายการใดเป็นอุปกรณ์หรือของใช้จำเป็นตาม DOM-INV-02 และ reorder_point บังคับหรือไม่ รอการตัดสินใจทีม (ค่าตัวเลขของแต่ละรายการยังไม่มี)
- ยังไม่มีหมายเลข Q: ใครเป็นเจ้าของข้อมูลสมาชิก (ไม่ใช้กับฟีเจอร์นี้โดยตรง; บันทึกเพื่อเทียบกับ 001, 003, 005)
- คำถามข้อเสนอ UI (ไม่มี ID): หน้ารายการอุปกรณ์ควรมีช่องค้นหาและแสดงจำนวนคงเหลือของแต่ละรายการใช่หรือไม่? (ยังไม่มีหมายเลข Q)
- คำถามข้อเสนอ UI (ไม่มี ID): รายการที่ถึง Reorder Point ควรแยกให้เห็นชัดจากรายการปกติในหน้ารายการอุปกรณ์ใช่หรือไม่? (ยังไม่มีหมายเลข Q)
- คำถามข้อเสนอ UI (ไม่มี ID): ฟอร์มเบิกหรือยืมควรบังคับกรอกผู้รับผิดชอบ วัตถุประสงค์ และวันกำหนดคืน (เมื่อเป็นการยืม) ใช่หรือไม่? (ยังไม่มีหมายเลข Q)
