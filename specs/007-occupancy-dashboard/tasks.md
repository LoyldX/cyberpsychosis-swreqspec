- Feature: Occupancy Dashboard (`007-occupancy-dashboard`)
- Spec ID: FR-BI-01, NFR-PERF-02, DOM-CAP-01, IF-GATE-01 (ยังไม่มี AC รอทีมกำหนด)
- อ้างอิง plan.md: `specs/007-occupancy-dashboard/plan.md`
- วันที่: 4 ตุลาคม 2569
- สรุป: ทั้งหมด 7 task, พร้อมทำ 0, รอ Q อย่างน้อย 1 ข้อ 5, รอการตัดสินใจทีมอย่างน้อย 1 เรื่อง 5 (task ที่รอทั้งสองแบบนับทั้งสองช่อง)
- หมายเหตุ: ไฟล์ตามโครงค่าเริ่มต้น (React Vite / FastAPI) ทีมเลือกเอง ไม่ได้มาจาก spec
- หมายเหตุ: ทุก task ต้องรอการตัดสินใจทีมเรื่องโครงโปรเจกต์ (ดูหมายเหตุ 001)
- หมายเหตุ: ตรวจด้วยใช้ ID ของ spec แทน AC จนกว่าทีมจะกำหนด AC

## รายการ task

### T-01 สร้างโครงข้อมูล gate event และ occupancy state
- รองรับ: FR-BI-01, DOM-CAP-01
- ตรวจด้วย: ยังไม่มี AC รอทีมกำหนด (อ้าง DOM-CAP-01 แทน)
- ไฟล์ที่แตะ: `backend/app/models/gate_event.py`, `backend/app/models/occupancy_state.py`
- ต้องทำหลัง: โครงโปรเจกต์ (ดูหมายเหตุ 001)
- เสร็จเมื่อ: model มี event_id, direction, event_time, current_count, last_event_id และ import ได้
- สถานะ: รอ Q3; รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001)

### T-02 รับ event จากประตูผ่าน POST
- รองรับ: IF-GATE-01, DOM-CAP-01
- ตรวจด้วย: ยังไม่มี AC รอทีมกำหนด (อ้าง IF-GATE-01 แทน)
- ไฟล์ที่แตะ: `backend/app/api/gate_events.py`, `backend/tests/test_occupancy.py`
- ต้องทำหลัง: T-01
- เสร็จเมื่อ: POST `/integrations/gate/events` รับ event ตามรูปแบบที่ทีมกำหนดและบันทึกลง gate event ได้
- สถานะ: รอ Q3; รอการตัดสินใจทีม: รูปแบบสัญญาณและโปรโตคอลของ IF-GATE-01 (ยังไม่มีหมายเลข Q)

### T-03 คำนวณจำนวนผู้ใช้บริการตาม DOM-CAP-01
- รองรับ: DOM-CAP-01, FR-BI-01
- ตรวจด้วย: ยังไม่มี AC รอทีมกำหนด (อ้าง DOM-CAP-01 แทน)
- ไฟล์ที่แตะ: `backend/app/services/occupancy_calc.py`, `backend/tests/test_occupancy.py`
- ต้องทำหลัง: T-01
- เสร็จเมื่อ: ผ่านเข้าเพิ่ม 1 และผ่านออกลด 1 ตามกฎที่ตอบแล้ว
- สถานะ: รอ Q3; รอ Q8

### T-04 สร้าง GET จำนวนผู้ใช้บริการปัจจุบัน
- รองรับ: FR-BI-01
- ตรวจด้วย: ยังไม่มี AC รอทีมกำหนด (อ้าง FR-BI-01 แทน)
- ไฟล์ที่แตะ: `backend/app/api/dashboard.py`, `backend/tests/test_occupancy.py`
- ต้องทำหลัง: T-03
- เสร็จเมื่อ: GET `/dashboard/occupancy` คืนจำนวนปัจจุบันจาก occupancy state
- สถานะ: รอ Q3

### T-05 ทำให้ตัวเลขอัปเดตอัตโนมัติ
- รองรับ: NFR-PERF-02
- ตรวจด้วย: ยังไม่มี AC รอทีมกำหนด (อ้าง NFR-PERF-02 แทน)
- ไฟล์ที่แตะ: `backend/app/services/occupancy_push.py`, `backend/tests/test_occupancy_refresh.py`
- ต้องทำหลัง: T-04
- เสร็จเมื่อ: เมื่อมี event ใหม่ จำนวนล่าสุดถูกส่งให้หน้า Dashboard ที่เปิดอยู่
- สถานะ: รอการตัดสินใจทีม: รอบเวลาอัปเดตของ NFR-PERF-02 (ยังไม่มีหมายเลข Q)

### T-06 สร้างหน้า Dashboard ด้วยข้อมูลจำลอง
- รองรับ: FR-BI-01
- ตรวจด้วย: ยังไม่มี AC รอทีมกำหนด (อ้าง FR-BI-01 แทน)
- ไฟล์ที่แตะ: `frontend/src/pages/OccupancyDashboard.jsx`, `frontend/src/api/mockOccupancy.js`
- ต้องทำหลัง: โครงโปรเจกต์ (ดูหมายเหตุ 001) (ใช้ข้อมูลจำลองตามสัญญา API ใน plan.md ข้อ 4 ไม่รอ T-04)
- เสร็จเมื่อ: หน้าจอแสดงจำนวนปัจจุบันเป็นข้อมูลหลักจากข้อมูลจำลอง
- สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI Dashboard; รอการตัดสินใจทีม: การล็อกอินและสิทธิ์การดูของผู้จัดการ

### T-07 ต่อ Dashboard กับ API จริง
- รองรับ: FR-BI-01, NFR-PERF-02
- ตรวจด้วย: ยังไม่มี AC รอทีมกำหนด (อ้าง FR-BI-01 แทน)
- ไฟล์ที่แตะ: `frontend/src/api/occupancy.js`, `frontend/src/pages/OccupancyDashboard.jsx`
- ต้องทำหลัง: T-04, T-05, T-06
- เสร็จเมื่อ: Dashboard อ่านจำนวนจาก GET `/dashboard/occupancy` จริงและอัปเดตตาม T-05
- สถานะ: รอ Q3; รอการตัดสินใจทีม: รอบเวลาอัปเดตของ NFR-PERF-02; รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI Dashboard
