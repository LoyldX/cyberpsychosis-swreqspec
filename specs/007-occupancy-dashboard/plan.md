# แผน: Occupancy Dashboard
Spec: `specs/007-occupancy-dashboard/spec.md` (Draft v1) | สร้างเมื่อ 4 ตุลาคม 2569 | หน้านี้เป็นผลลัพธ์ที่ AI ร่าง คนตรวจต้องยืนยัน

## 1. สรุปแนวทาง
ระบบรับ event การผ่านประตูจาก gate ตาม IF-GATE-01 และคำนวณจำนวนผู้ใช้บริการตาม DOM-CAP-01 (ผ่านเข้า +1 ผ่านออก -1)
Dashboard แสดงจำนวนปัจจุบันตาม FR-BI-01 และอัปเดตอัตโนมัติตาม NFR-PERF-02
การบันทึกขาออกยังรอ Q3 ซึ่งมีผลต่อกฎ DOM-CAP-01 ทั้งหมด จึงยังไม่ทำตรรกะการลดจำนวนจนกว่าจะตอบ
รูปแบบสัญญาณ gate และรอบเวลาอัปเดตยังไม่ระบุใน refine-req

## 2. เทคโนโลยีที่ใช้
| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| Interface รับข้อมูล gate | IF-GATE-01 | โปรโตคอลและรูปแบบสัญญาณยังไม่ระบุ (ไม่มีหมายเลข Q) |
| หน้าบ้าน Dashboard: React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้กับหน้าจอ Dashboard (ข้อเสนอ ยังไม่ยืนยัน) |
| หลังบ้าน: Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นของรายวิชา |
| วิธีส่งค่าอัปเดตไปยังหน้าจอ | ทีมเลือกเอง ไม่ได้มาจาก spec | ยังไม่ระบุ (รอรอบเวลาอัปเดตจากทีม) |

## 3. โมเดลข้อมูล
| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Gate event | `event_id`, `direction` (ขาเข้า / ขาออก), `event_time` (เวลาเหตุการณ์) | IF-GATE-01, DOM-CAP-01 |
| Occupancy state | `current_count` (จำนวนปัจจุบัน), `last_event_id` (เหตุการณ์ล่าสุดที่ประมวลผล) | FR-BI-01, DOM-CAP-01 |

- ค่า `direction` ที่เป็นขาออกจะถูกใช้เมื่อ Q3 ตอบว่าบันทึกขาออก

## 4. API / หน้าจอ
| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| POST `/integrations/gate/events` | event เข้า/ออก / ผลการรับ event | IF-GATE-01, DOM-CAP-01 |
| GET `/dashboard/occupancy` | เวลาอ้างอิง / จำนวนผู้ใช้บริการปัจจุบัน | FR-BI-01 |
| หน้าจอ Occupancy Dashboard (ข้อเสนอ ยังไม่ยืนยัน) | จำนวนปัจจุบัน / ผลการแสดงผลบนหน้าจอ | FR-BI-01, NFR-PERF-02 |

## 5. ตารางตรวจ Constraints
| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| IF-GATE-01 | POST `/integrations/gate/events` (ข้อ 4) รับ event จากประตู | ใช้แล้ว (โปรโตคอลยังไม่กำหนด) |
| DOM-CAP-01 | Occupancy state และการคำนวณ +1/-1 (ข้อ 3) | ใช้แล้ว (ทิศทางขาออกรอ Q3) |

## 7. ลำดับงาน
1. T-01 สร้างโครงข้อมูล gate event และ occupancy state (รองรับ: FR-BI-01, DOM-CAP-01; สถานะ: รอ Q3; รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001))
2. T-02 รับ event จากประตูผ่าน POST (รองรับ: IF-GATE-01, DOM-CAP-01; สถานะ: รอ Q3; รอการตัดสินใจทีม: รูปแบบสัญญาณและโปรโตคอลของ IF-GATE-01 (ยังไม่มีหมายเลข Q))
3. T-03 คำนวณจำนวนผู้ใช้บริการตาม DOM-CAP-01 (รองรับ: DOM-CAP-01, FR-BI-01; สถานะ: รอ Q3; รอ Q8)
4. T-04 สร้าง GET จำนวนผู้ใช้บริการปัจจุบัน (รองรับ: FR-BI-01; สถานะ: รอ Q3)
5. T-05 ทำให้ตัวเลขอัปเดตอัตโนมัติ (รองรับ: NFR-PERF-02; สถานะ: รอการตัดสินใจทีม: รอบเวลาอัปเดตของ NFR-PERF-02 (ยังไม่มีหมายเลข Q))
6. T-06 สร้างหน้า Dashboard ด้วยข้อมูลจำลอง (รองรับ: FR-BI-01; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI Dashboard; รอการตัดสินใจทีม: การล็อกอินและสิทธิ์การดูของผู้จัดการ)
7. T-07 ต่อ Dashboard กับ API จริง (รองรับ: FR-BI-01, NFR-PERF-02; สถานะ: รอ Q3; รอการตัดสินใจทีม: รอบเวลาอัปเดตของ NFR-PERF-02; รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI Dashboard)

## 8. สิ่งที่ยังไม่ทำ
- **Q3** ประตูทางเข้ายิมบันทึกทั้งขาเข้าและขาออกหรือไม่
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (ค่า direction ขาออกใน T-01, T-02, การคำนวณ -1 ใน T-03, T-04, T-07)
- **Q8** ข้อมูลลงทะเบียนเกี่ยวข้องกับการนับคนเข้ายิมและไฟล์ Excel เดิมหรือไม่
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (T-03)
- **Q10** ปัญหาเครื่องเล่น: อยู่นอกขอบเขตตามค่าเริ่มต้น ไม่สร้างสิ่งใดเพิ่มจนกว่าทีมจะตอบ
- ยังไม่มีหมายเลข Q: รอบเวลาอัปเดตของ NFR-PERF-02 จะยังไม่สร้าง T-05 จนกว่าทีมจะกำหนด
- ยังไม่มีหมายเลข Q: รูปแบบสัญญาณและโปรโตคอลของ IF-GATE-01 จะยังไม่สร้าง T-02 จนกว่าทีมจะกำหนด
- ยังไม่มีหมายเลข Q: การล็อกอินและสิทธิ์การดู Dashboard ของผู้จัดการ จะยังไม่สร้างการตรวจสิทธิ์ใน T-06
- ยังไม่มีหมายเลข Q: ข้อเสนอ UI Dashboard จะยังไม่สร้างหน้าจอจนกว่าทีมจะยืนยัน (T-06, T-07)
