# Feature: ลงทะเบียนเข้าใช้ยิม (QR Code / ออนไลน์ล่วงหน้า)
Spec ID: FR-REG-01 (Candidate) | Source: `draft/refine-req.md` (v5) §3, §4, §5, §6.2 | Status: Draft v2 — ยังไม่ผ่าน clarify | อัปเดต: 4 ตุลาคม 2569

> **สถานะของ spec นี้:** ทุก ID ในสเปคนี้เป็น 🆕 Candidate ใน refine-req v5 ยังไม่ใช่ requirement จนทีมยืนยัน (Main Prior REQ ข้อ 1 ที่ทีมต้องตัดสินใจ) ดู Q12 เรื่องลำดับความสำคัญ

## Goal
ลดคิวหน้าจุดลงทะเบียนเข้าใช้ยิม โดยให้ผู้ใช้บริการลงทะเบียนด้วยการสแกน QR Code หรือลงทะเบียนออนไลน์ล่วงหน้า แทนการเขียนลงกระดาษ (pain point ข้อ 1 ใน refine-req §1: ลืมปากกา และมีคิวยาว 7–8 คน)

## Scope
### In scope (ทั้งหมดเป็น Candidate)
- FR-REG-01 ลงทะเบียนเข้าใช้ยิมผ่าน QR Code
- FR-REG-02 ลงทะเบียนออนไลน์ล่วงหน้า
- DOM-REG-01 ข้อมูลลงทะเบียนขั้นต่ำ: รหัสนักศึกษาและชื่อ-นามสกุล
- NFR-PERF-03 เวลาลงทะเบียนต่อคนสั้นพอไม่ให้เกิดคิวยาว (เกณฑ์ = TBD)
- UI-REG-01..04 (ดูหัวข้อ Candidate)
- CON-DB-01 (accepted) การเก็บข้อมูลลงทะเบียนใน relational database ขึ้นกับ Q8
### Out of scope
- ระบบเช็กสถานะเครื่องเล่นและคิวเครื่องเล่น (Q10)
- ตัดออกทั้งระบบ (refine-req §2.1–2.2): POS และการขายหน้าร้าน; เครื่องสแกนเวลาและการซิงค์ HR; Data Privacy & Encryption (TLS 1.3, AES-256, PDPA); Nutrition (FR-NUT-01, IF-NUT-01)
- ผู้ใช้ที่ไม่มีรหัสนักศึกษา: ยังไม่มีแนวทาง (Q7)

## Constraints
- CON-DB-01 ใช้ PostgreSQL หรือ MySQL จัดเก็บข้อมูลลงทะเบียน **ถ้า** Q8 ตอบว่าเก็บใน CON-DB-01 (ชนิดฐานข้อมูลรอ Q4; ค่าเดาคือ PostgreSQL)

## Requirements (ยอมรับแล้ว)
ไม่มี requirement ที่ยอมรับแล้วในสเปคนี้ ทั้งหมดอยู่ในหัวข้อ Candidate ด้านล่าง

## Quality Requirements
ไม่มีที่ยอมรับแล้วในสเปคนี้ (NFR-PERF-03 เป็น Candidate ดูหัวข้อด้านล่าง)

## Assumptions & Open Questions
- **Q6** การลงทะเบียนต้องมีทั้ง QR Code และออนไลน์ล่วงหน้า หรือเลือกอย่างเดียว / ใครเป็นฝ่ายสแกน QR / ต้องลงทะเบียนทุกครั้งหรือครั้งเดียว (ยังไม่มีคำตอบ ผู้ตอบที่น่าจะได้: ผู้ดูแลยิม / Product Owner)
- **Q7** ผู้ใช้บริการมีเฉพาะนักศึกษาหรือไม่ และผู้ที่ไม่มีรหัสนักศึกษาลงทะเบียนอย่างไร (ยังไม่มีคำตอบ ค่าเดาคือมีเฉพาะนักศึกษา)
- **Q8** ข้อมูลลงทะเบียนเกี่ยวข้องกับการนับคนเข้ายิม (IF-GATE-01, FR-BI-01) และไฟล์ Excel เดิมหรือไม่ (ยังไม่มีคำตอบ ค่าเดาคือแยกกัน)
- **Q11** เป้าหมายเวลาลงทะเบียนต่อคนและความยาวคิวสูงสุดที่ยอมรับได้ (ยังไม่มีคำตอบ)
- **Q12** "Main Prior REQ" หมายถึงลำดับความสำคัญสูงสุดหรือความต้องการเดิม (ยังไม่มีคำตอบ ค่าเดาคือลำดับความสำคัญสูงสุด)
- ไม่มี ASM ใหม่ และไม่มีการกำหนดตัวเลขเอง
