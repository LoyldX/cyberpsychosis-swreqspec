## ควรทำอะไรต่อ (ตามคำสั่งของอาจารย์)

ลำดับต่อฟีเจอร์: **`/clarify` → `/plan` → `/tasks` → `/implement T-xx`**
คำสั่งอยู่ใน `.claude/commands/` (Claude Code), `.github/prompts/` (Copilot) และ `.cursor/commands/` (Cursor) ทำทีละฟีเจอร์ ทีละขั้น และ **ห้ามข้ามขั้น**

### ขั้นที่ 1 — `/clarify specs/00N-<feature>/spec.md`

1. AI อ่าน spec แล้วตอบ 3 ส่วนแล้ว **หยุดรอ**: A) จุดที่กำกวม/ขัดแย้ง/ทดสอบไม่ได้ B) คำถามไม่เกิน 8 ข้อ (บอกว่าถ้าไม่ตอบ AI จะเดาอะไร และควรถามใคร) C) สิ่งที่ AI ต้องเดาถ้าเริ่มเขียนโค้ดตอนนี้
2. ทีมตอบในแชตเดิม ตอบได้ 2 แบบเท่านั้น: "รู้ เพราะ..." หรือ "ไม่รู้ ต้องถาม..." **ห้ามตอบเพื่อให้ AI เลิกถาม**
3. AI แก้ spec: คำตอบที่ทีมตัดสินเองเป็น `ASM-xx` คำถามที่ยังไม่รู้เป็น `Q-xx` (พร้อมระบุว่าต้องถามใคร) ใช้ ID เดิม ห้ามเพิ่ม FR ใหม่ แล้วเปลี่ยน Status เป็น **Draft v2**
4. **ผลลัพธ์:** `spec.md` v2 + บันทึกใน `prompt-log.md`
5. **ตรวจก่อน commit:** diff ตรงกับบันทึกใน prompt-log, ไม่มี ID ใหม่, มี `Q-xx` อย่างน้อยเท่าที่จริงไม่รู้ (ทีมที่ไม่มี Q-xx เลยจะถูกตรวจละเอียดขึ้น) และ commit v2 แยกจาก v1

### ขั้นที่ 2 — `/plan specs/00N-<feature>/spec.md`

1. AI สร้าง `plan.md` 8 หัวข้อ: สรุปแนวทาง / เทคโนโลยี / โมเดลข้อมูล / API-หน้าจอ / **ตารางตรวจ Constraints** / แผนทดสอบจาก AC / ลำดับงาน / สิ่งที่ยังไม่ทำ (คัดลอก Open Questions)
2. ถ้า spec ยังเป็น Draft v1 คำสั่งจะเตือน ให้กลับไปทำขั้นที่ 1 ก่อน
3. **ตรวจ plan ก่อน commit:**
   - ตารางตรวจ Constraints มีครบทุก CON/DOM/IF ของ spec นั้น (นับเทียบกับ spec)
   - เทคโนโลยีที่ไม่ได้มาจาก Constraint ถูกกำกับว่า "ทีมเลือกเอง ไม่ได้มาจาก spec"
   - ทุก AC มี test และชื่อ test มี AC ID (เช่น `test_AC_BKG_01`)
   - Open Questions ทุกข้อถูกคัดลอกไว้ **โดยที่ AI ไม่ได้ตอบเอง**
   - ค้นหา `FR-`/`AC-` ใน plan แล้วไม่พบ ID ที่ไม่มีใน spec และไม่มีฟีเจอร์ที่ไม่มีใครขอ (เช่น "ลืมรหัสผ่าน")
4. พบข้อผิดพลาดของ AI ให้สั่งแก้ในแชตเดิม อ้างกติกาใน `AGENTS.md` แล้วจดใน `prompt-log.md`

### ขั้นที่ 3 — `/tasks specs/00N-<feature>/plan.md`

1. ต้องมี `plan.md` ก่อน (ถ้าไม่มีคำสั่งจะหยุด) AI สร้าง `tasks.md` เป็น `T-01, T-02, ...` แต่ละ task ระบุ: รองรับ (FR/NFR/CON/IF) / ตรวจด้วย (AC) / ไฟล์ที่แตะ / ต้องทำหลัง / เสร็จเมื่อ / สถานะ (`พร้อมทำ` หรือ `รอ Q-xx`)
2. **ตรวจก่อน commit:** ตารางท้ายไฟล์ครบ (ทุก AC มี task ตรวจ, ทุก Constraint มี task ทำให้เป็นจริง), task ที่ติด Open Question เป็น `รอ Q-xx` **ไม่ถูกเดาให้เดินต่อ**, แต่ละ task ไม่เกิน 1–2 ชั่วโมง
3. AI จะ **ไม่เริ่มทำ task ใด ๆ** จนกว่าทีมสั่งแยก

### ขั้นที่ 4 — `/implement T-xx`

1. สั่งทีละ task โดยระบุ ID เสมอ (เช่น `/implement T-01`) AI ปฏิเสธถ้า task เป็น `รอ Q-xx` หรือ task ใน "ต้องทำหลัง" ยังไม่ `เสร็จ` — ต้องปิด `Q-xx` ใน spec ก่อน
2. AI แตะ **เฉพาะไฟล์ที่ระบุใน task**, เขียนคอมเมนต์ว่ารองรับ FR/CON/IF ข้อใด, เขียน test ชื่อมี AC ID, รันและแสดงผลจริง (แก้ไม่เกิน 3 รอบ) แล้วเปลี่ยนสถานะเป็น `เสร็จ รอทีมตรวจ`
3. **ตรวจก่อน commit:** ไฟล์ที่แตะตรงกับ task, test ผ่านจริง, Constraint เห็นในโค้ดจริง จากนั้นค่อยสั่ง task ถัดไป AI จะไม่ทำต่อเอง
