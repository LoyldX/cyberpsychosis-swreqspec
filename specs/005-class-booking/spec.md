## Goal
สมาชิกเลือกและจองคลาสออกกำลังกายออนไลน์ได้สำเร็จ และไม่เกิดการจองซ้อนเมื่อเทรนเนอร์ติดสอนคลาสอื่นหรืออยู่นอกเวลาปฏิบัติงาน

## Scope
### In scope
- FR-BKG-01 จองคลาสออกกำลังกายออนไลน์
- FR-BKG-02 บล็อกคิวอัตโนมัติเมื่อเทรนเนอร์ไม่ว่าง
- NFR-PERF-01 ตรวจคิวว่างและบล็อกคิวทันที
### Out of scope (use case ข้างเคียง)
- ยกเลิกการจอง และดูรายการจองของตนเอง (SRS ไม่มี FR)
- สร้างคลาสและกำหนดช่วงเวลาเปิดรับ (SRS ไม่มี FR)
- ดูสถานะการจองผ่าน LINE Bot (FR-LINE-01 ไม่ทำใน sprint นี้)
- แจ้งเตือนผลการจอง (FR-NOTI-01), ชำระเงิน/POS
- จัดตารางเทรนเนอร์ (spec 004)
- รายการที่ตัดออกทั้งระบบ: ดู `docs/specs.md` §1.2
### Preconditions (ถือว่าเสร็จแล้ว)
- สมาชิกล็อกอินแล้ว (spec 001)
- มีตารางงานเทรนเนอร์อยู่แล้ว (spec 004)
- มีคลาสที่ฟิตเนสเปิดให้ผู้เข้าใช้เข้ามาเล่นได้สร้างไว้แล้ว (ผู้สร้างยังไม่กำหนด)

## Constraints
| ID | ประเภท | ข้อกำหนด (ตาม SRS §5.1, §7) |
|---|---|---|
| CON-DB-01 | CON | ใช้ PostgreSQL เก็บข้อมูลการจอง (ตอบ Q4 แล้ว) |

| CON-TECH-02 | CON | ใช้ React (Vite) เป็นเว็บแอปพลิเคชันอย่างเดียว (ไม่มีแอปมือถือเนทีฟ) |
| DOM-BKG-01 | DOM | สมาชิกไม่สามารถจองคลาสในช่วงที่เทรนเนอร์มีคิวสอนอื่นอยู่แล้วหรืออยู่นอกกะเวลาทำงาน |

- IF: ไม่มีใน spec นี้
- พฤติกรรมเมื่อฐานข้อมูลไม่ตอบสนอง: **ยังไม่กำหนด** (ดู Open Questions)

## Requirements (ยอมรับแล้ว)
| ID | ข้อกำหนด |
|---|---|
| FR-BKG-01 | **จองคลาสออกกำลังกายออนไลน์**: สมาชิกเลือกและจองคลาสที่เปิดรับผ่านระบบออนไลน์ได้ |
| FR-BKG-02 | **บล็อกคิวอัตโนมัติเมื่อเทรนเนอร์ไม่ว่าง**: ระบบตรวจสอบและบล็อกการจองซ้อนทันทีเมื่อเทรนเนอร์ติดสอนคลาสอื่นหรือไม่อยู่ในเวลาปฏิบัติงาน |

## Acceptance Criteria (ร่าง รอทีมยืนยัน)
- [ ] **AC-BKG-01** (FR-BKG-01) **Given** สมาชิกที่ล็อกอินแล้ว และคลาสที่เปิดรับซึ่งเทรนเนอร์ว่างและอยู่ในกะ **When** สมาชิกจองคลาสนั้น **Then** การจองสำเร็จและเรียกดูการจองนั้นได้
- [ ] **AC-BKG-02** (FR-BKG-02, DOM-BKG-01) **Given** เทรนเนอร์มีคลาส X เวลา 10:00–11:00 **When** สมาชิกจองคลาส Y ของเทรนเนอร์เดียวกันเวลา 10:30–11:30 **Then** ระบบบล็อกการจองและไม่บันทึกการจอง Y
- [ ] **AC-BKG-03** (FR-BKG-02, DOM-BKG-01) **Given** เทรนเนอร์มีกะ 09:00–12:00 **When** สมาชิกจองคลาสที่เริ่มก่อน 09:00 **Then** ระบบบล็อกการจอง
- [ ] **AC-BKG-04** (FR-BKG-02, DOM-BKG-01) **Given** เทรนเนอร์มีกะ 09:00–12:00 **When** สมาชิกจองคลาสที่เริ่ม 11:30 และจบ 12:30 **Then** ระบบบล็อกการจอง
- [ ] **AC-BKG-05** (NFR-PERF-01) **Given** คลาส X และ Y ของเทรนเนอร์เดียวกันมีเวลาทับซ้อนกัน และสมาชิกสองคนที่ล็อกอินแล้ว **When** ส่งคำขอจอง X และ Y พร้อมกัน **Then** สำเร็จเพียงรายการเดียว อีกรายการถูกบล็อก

## Assumptions & Open Questions
### Assumptions
- **ASM-01** “คลาสที่เปิดรับ” หมายถึงคลาสที่ฟิตเนสเปิดให้ผู้เข้าใช้เข้ามาเล่นได้ (ทีมชี้แจงเมื่อ 11 พฤศจิกายน 2569)

### Open Questions
| รหัส | คำถาม | ผู้ตอบที่น่าจะได้ |
|---|---|---|
| Q-01 | ค่า Latency ของ NFR-PERF-01 (SRS §8.1 ข้อ 5) คือเท่าใด — ห้ามใส่ตัวเลขเอง | Product Owner (เสนอ) |
| Q-02 | คลาสเป็นกลุ่มหรือเทรนเนอร์ 1 ต่อ 1 และมีจำนวนที่นั่งหรือไม่ (ห้ามสมมติ 1:1) | ผู้ดูแลยิม (เสนอ) |
| Q-03 | ใครสร้างคลาสและกำหนดช่วงเวลาเปิดรับจอง (ไม่มี FR รองรับ) | ผู้ดูแลยิม (เสนอ) |
| Q-04 | สมาชิกยกเลิกการจองและดูรายการจองของตนเองได้หรือไม่ (SRS ไม่มี FR) | Product Owner (เสนอ) |
| Q-05 | คลาสเต็ม คลาสไม่พบ หรือสมาชิกจองคลาสเดิมซ้ำ ระบบต้องทำอย่างไร (exception flow ที่ SRS ไม่มี FR) | Product Owner (เสนอ) |
| Q-06 | ใครเป็นเจ้าของข้อมูลสมาชิกที่ Booking อ้างถึง | Tech Lead (เสนอ) |
| Q-07 | เมื่อฐานข้อมูลไม่ตอบสนองระหว่างจอง ระบบต้องทำอย่างไร | Tech Lead (เสนอ) |
| Q-08 | ยืนยันหรือไม่ว่าให้บล็อกเฉพาะเวลาทับซ้อน โดยไม่บล็อกกรณีอยู่นอกกะตาม DOM-BKG-01 และ AC-BKG-03/04 | Product Owner / ผู้ดูแลยิม (เสนอ) |
| Q-09 | “คิวสอนอื่น” ที่ใช้ตรวจเวลาทับซ้อนหมายถึงคลาสอื่นของเทรนเนอร์คนเดียวกันเท่านั้น หรือรวมกิจกรรมสอนประเภทอื่นด้วย | ผู้ดูแลยิม (เสนอ) |
| Q-10 | หากยังบล็อกกรณีอยู่นอกกะ จะใช้ข้อมูลกะจากแหล่งใด และต้องพิจารณาวันหยุดหรือกะพิเศษหรือไม่ | ผู้ดูแลยิม / Team Lead (เสนอ) |

ข้อเสนอ UI (Candidate ไม่ใช่ requirement): UI-BKG-01 หน้าจองแสดงคลาสที่เปิดรับและไม่ให้เลือกช่วงที่ถูกบล็อก; UI-BKG-02 เมื่อถูกบล็อกแจ้งว่าจองไม่สำเร็จเพราะเทรนเนอร์ไม่ว่าง
