# Feature: จองคลาสออกกำลังกาย
Spec ID: FR-BKG-01, FR-BKG-02, DOM-BKG-01, NFR-PERF-01, CON-DB-01 | Source: `req/refine-req.md` (v5) | Status: Draft v1 | อัปเดต: 4 ตุลาคม 2569

## Goal
สมาชิกเลือกและจองคลาสออกกำลังกายที่เปิดรับผ่านระบบออนไลน์ โดยระบบบล็อกการจองซ้อนทันทีเมื่อเทรนเนอร์ติดสอนคลาสอื่นหรืออยู่นอกเวลาปฏิบัติงาน

## Scope
### In scope
- FR-BKG-01 จองคลาสออกกำลังกายออนไลน์
- FR-BKG-02 บล็อกคิวอัตโนมัติเมื่อเทรนเนอร์ไม่ว่าง
- DOM-BKG-01 กฎป้องกันคิวซ้อนของเทรนเนอร์
- NFR-PERF-01 การตรวจคิวว่างและการบล็อกคิวประมวลผลทันที
- CON-DB-01 ข้อมูลการจองเก็บใน relational database (ชนิดฐานข้อมูลยังรอ Q4)
### Out of scope
- ตัดออกทั้งระบบ (refine-req §2.1–2.2): POS และการขายหน้าร้าน; เครื่องสแกนเวลาและการซิงค์ HR; Data Privacy & Encryption (TLS 1.3, AES-256, PDPA); Nutrition (FR-NUT-01, IF-NUT-01); ระบบเช็กสถานะเครื่องเล่นและคิวเครื่องเล่น (Q10)

## Constraints
- CON-DB-01 ใช้ PostgreSQL หรือ MySQL จัดเก็บข้อมูลการจอง (ยังไม่เลือก ดู Q4)

## Requirements (ยอมรับแล้ว)
| ID | ข้อกำหนด |
|---|---|
| FR-BKG-01 | **จองคลาสออกกำลังกายออนไลน์**: สมาชิกเลือกและจองคลาสที่เปิดรับผ่านระบบออนไลน์ได้ |
| FR-BKG-02 | **บล็อกคิวอัตโนมัติเมื่อเทรนเนอร์ไม่ว่าง**: ระบบตรวจสอบและบล็อกการจองซ้อนทันที เมื่อเทรนเนอร์ติดสอนคลาสอื่นหรือไม่อยู่ในเวลาปฏิบัติงาน |

## Assumptions & Open Questions
- ยังไม่มีหมายเลข Q: ค่า latency ของ NFR-PERF-01 เป็นตัวเลขเท่าใด (refine-req §8.1 ข้อ 5 ระบุว่า "Real-time" ไม่มีตัวเลข)
- ยังไม่มีหมายเลข Q: คลาสเป็นกลุ่มหรือเทรนเนอร์ 1 ต่อ 1 (กำหนดว่าคลาสหนึ่งรับผู้จองได้กี่คน; spec ไม่ได้กำหนดจำนวนผู้จองต่อคลาส จึงไม่สมมติว่าเป็น 1 คนต่อคลาส)
- ยังไม่มีหมายเลข Q: ใครเป็นผู้สร้างคลาส (ไม่มี FR รองรับการสร้างคลาส)
- ยังไม่มีหมายเลข Q: ใครเป็นเจ้าของข้อมูลสมาชิก (member reference ใน Booking)
- **Q4** เลือก PostgreSQL หรือ MySQL (ยังไม่มีคำตอบ ค่าเดา: PostgreSQL ผู้ตอบที่น่าจะได้: Tech Lead) เกี่ยวกับ CON-DB-01
- คำถามข้อเสนอ UI (ไม่มี ID): หน้าจองคลาสควรไม่ให้เลือกช่วงเวลาที่ถูกบล็อก และแสดงข้อความว่าจองไม่สำเร็จเพราะเทรนเนอร์ไม่ว่างเมื่อถูกบล็อกใช่หรือไม่? (ยังไม่มีหมายเลข Q)
