# แผน: รักษา Session Login แบบ Persistent
Spec: `specs/001-auth-session/spec.md` (Draft v1) | สร้างเมื่อ 4 ตุลาคม 2569 | หน้านี้เป็นผลลัพธ์ที่ AI ร่าง คนตรวจต้องยืนยัน

## 1. สรุปแนวทาง
ระบบรับการเข้าสู่ระบบของสมาชิกและออก refresh token เพื่อรักษา session ตาม FR-AUTH-01 และเก็บข้อมูล session ใน Redis ตาม CON-CACHE-01
เป้าหมายคือให้สมาชิกไม่ต้องล็อกอินซ้ำโดยไม่จำเป็น (ลดการ Auto-logout) ตาม pain point ใน refine-req §1
เกณฑ์ความน่าเชื่อถือ (อัตราการหลุด) ตาม NFR-REL-01 วัดไม่ได้จนกว่าจะตอบ Q2
วิธีเข้าสู่ระบบ อายุ session และกลุ่มผู้ใช้ยังไม่กำหนด จึงยังไม่ใส่ค่า TTL หรือเงื่อนไขกลุ่มผู้ใช้ในโค้ด
หน้าจอเข้าใช้งานต่อเนื่องเป็นข้อเสนอที่ยังไม่ได้รับการยืนยัน จึงยังไม่สร้างจนกว่าทีมจะยืนยัน

## 2. เทคโนโลยีที่ใช้
| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| Redis | CON-CACHE-01 | เก็บข้อมูล session ตามข้อกำหนด |
| วิธีเข้าสู่ระบบของสมาชิก | ทีมเลือกเอง ไม่ได้มาจาก spec | ยังไม่มีในสเปค รอการตัดสินใจทีม |
| รูปแบบ refresh token | ทีมเลือกเอง ไม่ได้มาจาก spec | FR-AUTH-01 ระบุการใช้ Refresh Token แต่ไม่ระบุรูปแบบ |
| หน้าบ้าน: React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้กับหน้าจอเข้าใช้งานต่อเนื่อง (ข้อเสนอ ยังไม่ยืนยัน) |
| หลังบ้าน: Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นของรายวิชา |

## 3. โมเดลข้อมูล
| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Session (ใน Redis) | `session_id` (รหัส session), `member_id` (อ้างอิงสมาชิก), `refresh_token_state` (สถานะ refresh token), `expires_at` (เวลาหมดอายุ) | FR-AUTH-01, NFR-REL-01, CON-CACHE-01 |

- ค่า `expires_at` ยังไม่ถูกตั้งค่า รอ Q2
- ไม่มีตาราง relational สำหรับ session เพราะ spec ระบุ Redis

## 4. API / หน้าจอ
| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| POST `/auth/login` | ข้อมูลเข้าสู่ระบบของสมาชิก (วิธีรอการตัดสินใจทีม) / refresh token และ session | FR-AUTH-01 |
| POST `/auth/refresh` | refresh token / session ใหม่ | FR-AUTH-01 |
| หน้าจอเข้าใช้งานต่อเนื่อง (ข้อเสนอ ยังไม่ยืนยัน) | สถานะ session / เข้าหน้าหลักทันที | FR-AUTH-01, NFR-REL-01 |

## 5. ตารางตรวจ Constraints
| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-CACHE-01 | โมเดล Session (ข้อ 3) และ POST `/auth/login`, `/auth/refresh` (ข้อ 4) ใช้ Redis เป็นที่เก็บ | ใช้แล้ว |

## 6. แผนทดสอบ
ยังไม่มี AC ใน spec รอทีมกำหนด AC

สมมติฐาน: จนกว่าทีมจะกำหนด AC ให้ตั้งชื่อ test ตาม ID ที่มีใน spec เช่น `test_FR_AUTH_01_...`, `test_NFR_REL_01_...`, `test_CON_CACHE_01_...` และไม่อ้าง AC ใด

## 7. ลำดับงาน
1. T-01 สร้างโครงข้อมูล session ใน Redis (รองรับ: FR-AUTH-01, CON-CACHE-01; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: วิธีรัน Redis สำหรับ test; รอการตัดสินใจทีม: เจ้าของข้อมูลสมาชิก (`member_id`))
2. T-02 สร้างการเข้าสู่ระบบและออก refresh token (รองรับ: FR-AUTH-01, CON-CACHE-01; สถานะ: รอ Q2; รอ Q7; รอการตัดสินใจทีม: วิธีเข้าสู่ระบบของสมาชิก; รอการตัดสินใจทีม: วิธีรัน Redis สำหรับ test; รอการตัดสินใจทีม: เจ้าของข้อมูลสมาชิก)
3. T-03 สร้าง endpoint ต่ออายุ session ด้วย refresh token (รองรับ: FR-AUTH-01, CON-CACHE-01; สถานะ: รอ Q2; รอการตัดสินใจทีม: วิธีรัน Redis สำหรับ test)
4. T-04 วัดอัตราการหลุดของ session (รองรับ: NFR-REL-01, CON-CACHE-01; สถานะ: รอ Q2)
5. T-05 สร้างหน้าจอเข้าใช้งานต่อเนื่องด้วยข้อมูลจำลอง (รองรับ: FR-AUTH-01; สถานะ: รอ Q2; รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI เข้าใช้งานต่อเนื่อง (ดู Assumptions))
6. T-06 ต่อหน้าจอเข้าใช้งานต่อเนื่องกับ API จริง (รองรับ: FR-AUTH-01, CON-CACHE-01; สถานะ: รอ Q2; รอ Q7; รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI เข้าใช้งานต่อเนื่อง)

## 8. สิ่งที่ยังไม่ทำ
- **Q2** "User" ที่โดน Auto-logout คือผู้ใช้กลุ่มใด และ session ต้องคงอยู่นานเท่าใด
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (ค่า `expires_at`, T-02, T-03, T-04, T-05, T-06)
- **Q7** ผู้ใช้บริการมีเฉพาะนักศึกษาหรือไม่ และผู้ใช้ที่ไม่มีรหัสนักศึกษา (เช่น บุคลากร บุคคลภายนอก) ลงทะเบียนอย่างไร
  ผลต่อ FR-AUTH-01: วิธีเข้าสู่ระบบของผู้ไม่มีรหัสนักศึกษา
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (T-02, T-06)
- ยังไม่มีหมายเลข Q: สมาชิกเข้าสู่ระบบด้วยวิธีใด ยังไม่สร้าง T-02 จนกว่าทีมจะตัดสิน
- ยังไม่มีหมายเลข Q: เจ้าของข้อมูลสมาชิก ยังไม่สร้างฟิลด์ `member_id` จนกว่าทีมจะตัดสิน (T-01, T-02)
- คำถามข้อเสนอ UI เข้าใช้งานต่อเนื่อง: ยังไม่สร้างหน้าจอจนกว่าทีมจะยืนยัน (T-05, T-06)
