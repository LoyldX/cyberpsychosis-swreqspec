# Feature: Auth Session Persistence
Spec ID: FR-AUTH-01, NFR-REL-01, CON-CACHE-01, CON-DB-01 | Source: `docs/specs.md` §3.1 → `docs/srs/srs.md` v5.1 §3.1, §4.1, §7 | Use Case ID: ไม่มีใน SRS v5.1 (node ใน usecase.mmd: `uc_auth`) | Owner: _(รอมอบหมาย)_ | Status: Draft v2 (ผ่าน /clarify 2 รอบ ล่าสุด 8 พฤศจิกายน 2569) | Depends on: ไม่มี | Reviewed by: _(รอผู้ตรวจ — ร่างโดย AI)_ | อัปเดต: 8 พฤศจิกายน 2569

## Goal
สมาชิกที่เข้าสู่ระบบแล้ว กลับมาใช้เว็บอีกครั้งภายในอายุ Session แล้วใช้งานต่อได้ทันทีโดยไม่ต้องเข้าสู่ระบบใหม่ ระบบรักษา Session ด้วย Refresh Token ผ่าน Redis

### คำที่ใช้ในเอกสารนี้ (ใช้คำเดียวต่อสิ่งเดียว)
| คำ | ความหมาย |
|---|---|
| สมาชิก | ผู้ใช้บริการของยิมที่มีบัญชีในระบบ (ไม่ใช้ "ผู้ใช้"/"User" ยกเว้นเมื่ออ้างข้อความ SRS) |
| เข้าสู่ระบบ | การที่สมาชิกพิสูจน์ตัวตนด้วยรหัสนักศึกษาและรหัสผ่าน (ASM-01) |
| Session | ช่วงที่สมาชิกใช้งานต่อได้โดยไม่ต้องเข้าสู่ระบบใหม่ มีอายุเท่ากับ Refresh Token (ASM-02) |
| หลุดโดยไม่ตั้งใจ | สมาชิกต้องเข้าสู่ระบบใหม่ทั้งที่ Refresh Token ยังไม่หมดอายุ (ASM-08) |

## Scope
### In scope
- FR-AUTH-01 เข้าสู่ระบบของสมาชิกและรักษา Session ด้วย Refresh Token
- NFR-REL-01 การจัดการ Session ผ่าน Redis ร่วมกับ Refresh Token
### Out of scope (use case ข้างเคียง)
- ลงทะเบียนเข้าใช้ยิม และการตั้งรหัสผ่านเริ่มต้น (FR-REG-01/02 เป็น Candidate; ดู Q-03)
- ออกจากระบบ/เพิกถอน Refresh Token (spec ไม่มี FR; ดู ASM-03, Q-02)
- เข้าสู่ระบบของเจ้าหน้าที่/ผู้จัดการ (SRS ไม่กำหนด)
- Push Notification (FR-NOTI-01) และการผูกบัญชี LINE (Q5, LINE Bot ไม่ทำใน sprint นี้)
- รายการที่ตัดออกทั้งระบบ: ดู `docs/specs.md` §1.2
### Preconditions (ถือว่าเสร็จแล้ว)
- สมาชิกมีบัญชีและรหัสผ่านอยู่ในระบบแล้ว (ที่มายังไม่กำหนด ดู Q-03)

## Constraints
| ID | ประเภท | ข้อกำหนด (ตาม SRS §7) |
|---|---|---|
| CON-CACHE-01 | CON | ใช้ Redis บริหาร Session Login |
| CON-DB-01 | CON | ใช้ PostgreSQL เก็บข้อมูลสมาชิก (ตอบ Q4 แล้ว) |
| CON-TECH-01 | CON | ใช้ภาษา Go และ Gin framework พัฒนา Backend API |
| CON-TECH-02 | CON | ใช้ React (Vite) เป็นเว็บแอปพลิเคชันอย่างเดียว (ไม่มีแอปมือถือเนทีฟ) |

- DOM: ไม่มีใน spec นี้ | IF: ไม่มีใน spec นี้
- พฤติกรรมเมื่อ Redis หรือฐานข้อมูลไม่ตอบสนอง: ปฏิเสธและแจ้งให้ลองใหม่ (ASM-05) โดยถือว่า "ไม่ตอบสนอง" เมื่อเกิน 5 วินาที (ASM-09)

## Requirements (ยอมรับแล้ว)
| ID | ข้อกำหนด |
|---|---|
| FR-AUTH-01 | **รักษา Session Login แบบ Persistent**: รองรับการเข้าสู่ระบบของสมาชิกและรักษา Session ด้วย Refresh Token เพื่อป้องกันการถูก Auto-logout บ่อยครั้ง |

ข้อความ FR คัดจาก SRS ตรงตัว การตีความที่ทีมตัดสินอยู่ใน ASM-01 ถึง ASM-08 ด้านล่าง

## Quality Requirements (ยอมรับแล้ว)
| ID | ข้อกำหนด |
|---|---|
| NFR-REL-01 | Session Persistence & Reliability: การจัดการ Session ผ่าน Redis ร่วมกับ Refresh Token ต้องมีอัตราการหลุดโดยไม่ตั้งใจไม่เกินเกณฑ์ — อายุ Session และอัตราหลุดสูงสุด = **TBD** (Q2; ตัวเลขอัตราหลุด ดู Q-01) |

NFR-REL-01 ยังไม่มีตัวเลขอัตราหลุด จึงไม่มี AC (อายุ Session ใช้ค่าตาม ASM-02 ชั่วคราว)

## Acceptance Criteria (ร่าง รอทีมยืนยัน)
- [ ] **AC-AUTH-01** (FR-AUTH-01, ASM-01) **Given** สมาชิกที่มีบัญชีในระบบและกรอกรหัสนักศึกษากับรหัสผ่านถูกต้อง **When** เข้าสู่ระบบ **Then** ระบบส่ง Refresh Token กลับให้สมาชิก
- [ ] **AC-AUTH-02** (FR-AUTH-01, ASM-02) **Given** สมาชิกมี Refresh Token ที่ออกมาไม่เกิน 7 วัน **When** ขอใช้งานต่อด้วย Refresh Token นั้น **Then** ระบบยืนยันสมาชิกสำเร็จ และสมาชิกเรียกฟังก์ชันที่ต้องเข้าสู่ระบบได้โดยไม่ต้องกรอกรหัสนักศึกษาและรหัสผ่านใหม่
- [ ] **AC-AUTH-03** (FR-AUTH-01, ASM-02) **Given** Refresh Token ที่ออกมาเกิน 7 วันแล้ว **When** ขอใช้งานต่อด้วย Refresh Token นั้น **Then** ระบบปฏิเสธคำขอ
- [ ] **AC-AUTH-04** (FR-AUTH-01) **Given** Refresh Token ที่ไม่ใช่ของระบบหรือถูกแก้ไข **When** ขอใช้งานต่อด้วย Refresh Token นั้น **Then** ระบบปฏิเสธคำขอ
- [ ] **AC-AUTH-05** (CON-CACHE-01) **Given** สมาชิกเข้าสู่ระบบสำเร็จ **When** ตรวจ Redis ด้วย integration test **Then** พบรายการ Session ของสมาชิกนั้นใน Redis
- [ ] **AC-AUTH-06** (FR-AUTH-01, ASM-06) **Given** รหัสนักศึกษาที่ไม่มีในระบบ หรือรหัสผ่านที่ไม่ถูกต้อง **When** เข้าสู่ระบบ **Then** ระบบปฏิเสธ ไม่ส่ง Refresh Token และข้อความไม่บอกว่าผิดที่รหัสนักศึกษาหรือรหัสผ่าน
- [ ] **AC-AUTH-07** (CON-CACHE-01, ASM-05) **Given** Redis ไม่ตอบสนอง (เกิน 5 วินาที ตาม ASM-09) **When** สมาชิกขอใช้งานต่อด้วย Refresh Token ที่ถูกต้อง **Then** ระบบปฏิเสธและแจ้งให้ลองใหม่
- [ ] **AC-AUTH-08** (CON-DB-01, ASM-05) **Given** PostgreSQL ไม่ตอบสนอง (เกิน 5 วินาที ตาม ASM-09) **When** สมาชิกเข้าสู่ระบบ **Then** ระบบปฏิเสธและแจ้งให้ลองใหม่
- [ ] **AC-AUTH-09** (FR-AUTH-01, ASM-04) **Given** สมาชิกเข้าสู่ระบบแล้วบนอุปกรณ์ A **When** เข้าสู่ระบบบนอุปกรณ์ B **Then** Refresh Token ของอุปกรณ์ A ยังใช้ขอใช้งานต่อได้
- [ ] **AC-AUTH-10** (FR-AUTH-01, ASM-07) **Given** สมาชิกเข้าสู่ระบบบนเว็บแล้วภายในอายุ Session **When** ปิดเบราว์เซอร์แล้วเปิดเว็บใหม่ **Then** สมาชิกใช้งานต่อได้โดยไม่ต้องเข้าสู่ระบบใหม่
