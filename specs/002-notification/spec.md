# Feature: Push Notification
Spec ID: FR-NOTI-01 | Source: `docs/srs/srs.md` (v5) | Status: Draft v1 | อัปเดต: 4 ตุลาคม 2569

## Goal
ระบบต้องส่งข้อความแจ้งเตือนไปยังสมาชิกผ่านแอปพลิเคชันให้ทราบข้อมูลสำคัญที่เกี่ยวกับการใช้ยิม เช่น วันและเวลาเปิด-ปิดยิม และข่าวสารประชาสัมพันธ์ เพื่อแทนที่การได้รับข่าวสารผ่าน Facebook Page อย่างเดียว (pain point ข้อ 5 ใน refine-req §1)

## Scope
### In scope
- FR-NOTI-01 ส่ง push notification เรื่องวันและเวลาเปิด-ปิดยิม และข่าวสารประชาสัมพันธ์ไปยังสมาชิกที่ใช้งานแอปและมีสิทธิ์รับข้อมูล
### Out of scope
- ตัดออกทั้งระบบ (refine-req §2.1–2.2): POS และการขายหน้าร้าน; เครื่องสแกนเวลาและการซิงค์ HR; Data Privacy & Encryption (TLS 1.3, AES-256, PDPA); Nutrition (FR-NUT-01, IF-NUT-01); ระบบเช็กสถานะเครื่องเล่นและคิวเครื่องเล่น (Q10)

## Constraints
- ไม่มี CON, DOM หรือ IF ที่ระบุช่องทาง push ใน refine-req (บริการ push ที่ใช้ยังไม่กำหนด ทีมเลือกเอง ไม่ได้มาจาก spec)
- ข้อความแจ้งเตือนที่ส่งไปยังแอปสมาชิกจะต้องมีข้อมูลที่สามารถระบุได้ว่าเป็นวันและเวลาเปิด-ปิดยิม หรือเป็นข่าวสารประชาสัมพันธ์ แต่รูปแบบการแสดงผลและบริการ push provider ยังคงเป็นเรื่องที่ทีมเลือกเอง

## Requirements (ยอมรับแล้ว)
| ID | ข้อกำหนด |
|---|---|
| FR-NOTI-01 | **ส่ง Push Notification**: ระบบต้องส่งข้อความแจ้งเตือนวันและเวลาเปิด-ปิดยิม รวมถึงข่าวสารประชาสัมพันธ์ไปยังแอปของสมาชิกที่มีสิทธิ์รับข้อมูล โดยข้อความที่ส่งต้องสามารถระบุประเภทของข้อมูลว่าเป็นข้อมูลเปิด-ปิดยิมหรือข่าวสารประชาสัมพันธ์ได้ชัดเจน |

## Assumptions & Open Questions
- **Q9** Push Notification (FR-NOTI-01) จะมาแทน Facebook Page หรือใช้คู่กัน และระบบต้องโพสต์ไป Facebook Page ด้วยหรือไม่ (ยังไม่มีคำตอบ ค่าเดา: ใช้คู่กัน และระบบไม่เชื่อมต่อ Facebook ผู้ตอบที่น่าจะได้: ผู้ดูแลยิม / ฝ่ายประชาสัมพันธ์) เกี่ยวกับ FR-NOTI-01 — ความสัมพันธ์กับ Facebook Page ย้ายมาจาก Out of scope เพราะยังไม่ได้ตัดสิน
- ยังไม่มีหมายเลข Q: กลุ่มผู้รับข้อความคือสมาชิกทุกคนหรือเฉพาะกลุ่มใด และรอบเวลาการส่งข้อความเป็นแบบใด (refine-req ไม่ระบุ)
- ยังไม่มีหมายเลข Q: เจ้าของข้อมูลสมาชิก (ใช้เป็นผู้รับข้อความ) และรูปแบบการจัดการความยินยอมในการรับข้อความเป็นอย่างไร
- ยังไม่มีหมายเลข Q: ผู้มีสิทธิ์สร้างหรือส่งข้อความในระบบคือใคร และมีสิทธิ์แยกตามบทบาทหรือไม่
- ยังไม่มีหมายเลข Q: บริการ push ที่จะใช้สำหรับแอปสมาชิก (ทีมเลือกเอง ไม่ได้มาจาก spec)
- คำถามข้อเสนอ UI (ไม่มี ID): ข้อความแจ้งเตือนเรื่องเปิด-ปิดยิมควรแสดงวันและเวลาที่เปิด-ปิดหรือไม่? (UI-NOTI-01 ยังไม่ยืนยัน เกี่ยวข้องกับ Q9)
