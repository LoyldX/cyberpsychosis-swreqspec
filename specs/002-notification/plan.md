# แผน: Push Notification

## 1. สรุปแนวทาง

ระบบจะส่ง push notification ให้สมาชิกตาม FR-NOTI-01
ประเภทข้อความที่อยู่ในขอบเขตคือเวลาเปิด-ปิดยิมและข่าวสารประชาสัมพันธ์
หน้าจอหรือ service จะรับเนื้อหาการแจ้งเตือนและส่งไปยังแอปสมาชิก
รายละเอียดผู้รับและรอบเวลาการส่งยังไม่ระบุใน spec
จึงต้องยืนยันรายละเอียดก่อนวางแผนเชิง implementation

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| ระบบ push notification | FR-NOTI-01 | ผู้ให้บริการยังไม่ระบุ |
| หน้าบ้านและหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ยังไม่ระบุเทคโนโลยี |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Notification message | message content, notification category, member recipient | FR-NOTI-01 |

ฟิลด์เพิ่มเติมยังไม่กำหนดเพราะ spec ไม่ระบุ

## 4. API / หน้าจอ

| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| หน้าจอจัดการข่าวสาร | เนื้อหาและประเภทข้อความ / สถานะการส่ง | FR-NOTI-01 |
| POST `/notifications/send` | ข้อความและกลุ่มผู้รับ / ผลการส่ง | FR-NOTI-01 |

## 5. ตารางตรวจ Constraints

ไม่มี CON, DOM หรือ IF ใน spec นี้

## 6. แผนทดสอบจาก Acceptance Criteria

ยังไม่มี Acceptance Criteria ใน spec จึงยังสร้าง test ที่อ้าง AC ไม่ได้

## 7. ลำดับงาน

1. ระบุผู้มีสิทธิ์สร้างข่าวสารตาม FR-NOTI-01
2. กำหนดประเภทและผู้รับของข้อความตาม FR-NOTI-01
3. เลือกช่องทาง push โดยทีม เพราะ spec ไม่ได้ระบุ
4. ออกแบบการสร้างและส่งข้อความตาม FR-NOTI-01
5. เพิ่ม Acceptance Criteria และทดสอบการส่งสำเร็จ/ไม่สำเร็จ

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Question เฉพาะฟีเจอร์นี้ใน spec แต่รายละเอียดที่ source ไม่ได้ระบุจะยังไม่ถือเป็นข้อกำหนด
