# แผน: Push Notification
Spec: `specs/002-notification/spec.md` (Draft v2 — ยังไม่ผ่าน clarify) | สร้างเมื่อ 4 ตุลาคม 2569 | หน้านี้เป็นผลลัพธ์ที่ AI ร่าง คนตรวจต้องยืนยัน

## 1. สรุปแนวทาง
ระบบสร้างและส่ง push notification ไปยังแอปสมาชิกตาม FR-NOTI-01
ประเภทข้อความที่อยู่ในขอบเขตคือวันและเวลาเปิด-ปิดยิม และข่าวสารประชาสัมพันธ์
ผู้รับกลุ่มใด รอบเวลาการส่ง และความสัมพันธ์กับ Facebook Page ยังไม่ระบุ (Q9 และรายการที่ยังไม่มีหมายเลข Q)
จึงยังไม่กำหนดกฎการส่งที่ต้องทดสอบจริง และยังไม่เลือกบริการ push ให้ทีม

## 2. เทคโนโลยีที่ใช้
| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| บริการ push สำหรับแอปสมาชิก | FR-NOTI-01 | ยังไม่ระบุ ทีมต้องเลือกก่อนพัฒนา ไม่ได้มาจาก spec |
| หน้าบ้าน: React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เฉพาะหน้าจอประกาศข่าว (UI-NOTI-01 Candidate) |
| หลังบ้าน: Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นของรายวิชา |

## 3. โมเดลข้อมูล
| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Notification message | message content, notification category (เปิด-ปิดยิม / ข่าวสาร), member recipient, send status | FR-NOTI-01 |

- ฟิลด์เพิ่มเติม (เช่น ช่วงเวลาส่ง) ไม่สร้างเพราะ spec ไม่ระบุ

## 7. ลำดับงาน
1. ทีมเลือกบริการ push (ไม่มีใน spec จึงเป็นการตัดสินใจของทีม)
2. ระบุผู้มีสิทธิ์สร้างข่าวสาร (ยังไม่มีใน spec ต้องถามทีม)
3. ออกแบบข้อความ Notification message ตามประเภทใน FR-NOTI-01 (ข้อ 3)
4. สร้าง POST `/notifications/send` และส่งข้อความ (FR-NOTI-01, AC-NOTI-01)
5. ทดสอบการถึงแอปสมาชิก (AC-NOTI-02, รอ Q9 และผู้รับ/เวลาส่ง)
6. สร้างหน้าจอประกาศ (UI-NOTI-01 Candidate, รอ Q9)

## 8. สิ่งที่ยังไม่ทำ
- **Q9** Push Notification จะมาแทน Facebook Page หรือใช้คู่กัน และระบบต้องโพสต์ไป Facebook Page ด้วยหรือไม่
  ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ (การโพสต์ไป Facebook, UI-NOTI-01, AC-NOTI-02)
- ยังไม่มีหมายเลข Q: ผู้รับกลุ่มใดและรอบเวลาส่ง ยังไม่สร้างจนกว่าทีมจะกำหนดคำถามและคำตอบ
