# แผน: Trainer Roster

## 1. สรุปแนวทาง

ระบบจะให้เจ้าหน้าที่หรือผู้จัดการจัดตารางเทรนเนอร์ตาม FR-ROST-01
ผู้ใช้จะสร้างและปรับปรุงเวลาทำงานและเวลาสอนของเทรนเนอร์
ข้อมูลตารางจะถูกใช้เป็นข้อมูลประกอบการจองคลาส
สิทธิ์ผู้ใช้และรูปแบบตารางยังไม่ได้กำหนดใน spec
จึงต้องเก็บรายละเอียดเหล่านี้เป็นประเด็นที่ยังไม่ทำ

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| หน้าจอตารางเวลา | FR-ROST-01 | รูปแบบ UI ทีมเลือกเอง ไม่ได้มาจาก spec |
| หน้าบ้านและหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ยังไม่ระบุเทคโนโลยี |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Trainer roster | trainer reference, work interval, teaching interval | FR-ROST-01 |

## 4. API / หน้าจอ

| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| GET `/trainers/{trainerId}/roster` | trainer reference / ตารางปัจจุบัน | FR-ROST-01 |
| PUT `/trainers/{trainerId}/roster` | ตารางเวลาใหม่ / ตารางที่บันทึก | FR-ROST-01 |
| หน้าจอ Trainer Roster | ตารางงานและเวลาสอน / ผลการบันทึก | FR-ROST-01 |

## 5. ตารางตรวจ Constraints

ไม่มี CON, DOM หรือ IF ใน spec นี้

## 6. แผนทดสอบจาก Acceptance Criteria

ยังไม่มี Acceptance Criteria ใน spec จึงยังสร้าง test ที่อ้าง AC ไม่ได้

## 7. ลำดับงาน

1. ยืนยันสิทธิ์เจ้าหน้าที่และผู้จัดการที่เกี่ยวข้องกับ FR-ROST-01
2. ยืนยันรูปแบบเวลาทำงานและเวลาสอน
3. ออกแบบโมเดล Trainer roster ตาม FR-ROST-01
4. ออกแบบหน้าจอและ endpoint จัดการตาราง
5. กำหนดกฎตรวจข้อมูลตารางก่อนบันทึก
6. เพิ่ม Acceptance Criteria ก่อนทดสอบ

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Question เฉพาะฟีเจอร์นี้ใน spec แต่รายละเอียดสิทธิ์และรูปแบบตารางที่ source ไม่ได้ระบุจะยังไม่สร้างจนกว่าจะได้คำตอบจากทีม
