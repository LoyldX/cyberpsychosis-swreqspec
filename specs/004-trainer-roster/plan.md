## 1. สรุปแนวทาง
ระบบให้เจ้าหน้าที่หรือผู้จัดการจัดตารางงานเทรนเนอร์ (เวลาเข้างานและเวลาสอน) ตาม FR-ROST-01
ตารางนี้เก็บใน relational database ตาม CON-DB-01 และเป็นข้อมูลที่ 005 ใช้ตรวจการบล็อกคิว (ใช้โมเดลนี้ร่วมกัน ไม่สร้างซ้ำ)
ชนิดฐานข้อมูลยังรอ Q4 จึงออกแบบ repository เป็น interface ก่อน ไม่เชื่อมฐานข้อมูลจริง
การล็อกอินและสิทธิ์ของเจ้าหน้าที่ยังไม่มีใน spec จึงยังไม่สร้างการตรวจสิทธิ์

## 7. ลำดับงาน
1. T-01 สร้าง model และ repository interface ของ Trainer roster (รองรับ: FR-ROST-01, CON-DB-01; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: รูปแบบช่วงเวลาและตารางงาน (ยังไม่มีหมายเลข Q))
2. T-02 สร้าง GET/PUT ตารางงานเทรนเนอร์ด้วย fake repository (รองรับ: FR-ROST-01; สถานะ: รอการตัดสินใจทีม: การล็อกอินและสิทธิ์ของเจ้าหน้าที่/ผู้จัดการ; รอการตัดสินใจทีม: รูปแบบช่วงเวลาและตารางงาน)
3. T-03 เชื่อม repository กับฐานข้อมูลจริง (รองรับ: CON-DB-01, FR-ROST-01; สถานะ: รอ Q4; รอการตัดสินใจทีม: วิธีรัน Redis และฐานข้อมูลสำหรับ test)
4. T-04 สร้างหน้าจอ Trainer Roster ด้วยข้อมูลจำลอง (รองรับ: FR-ROST-01; สถานะ: รอการตัดสินใจทีม: โครงโปรเจกต์ (ดูหมายเหตุ 001); รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI ตารางงาน (ดู Assumptions))
5. T-05 ต่อหน้าจอกับ API จริง (รองรับ: FR-ROST-01, CON-DB-01; สถานะ: รอ Q4; รอการตัดสินใจทีม: ยืนยันข้อเสนอ UI ตารางงาน; รอการตัดสินใจทีม: การล็อกอินและสิทธิ์ของเจ้าหน้าที่/ผู้จัดการ)
