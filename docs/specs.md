## 0. วิธีใช้เอกสารนี้

- เอกสารนี้คือ **ความจริงหนึ่งเดียว** ของ sprint นี้ `specs/00N-<feature>/spec.md` ทุกไฟล์ต้องคัดมาจากที่นี่ และ `plan.md` ทุกไฟล์ต้องอ้างกลับมาที่ ID ในเอกสารนี้
- ถ้าเอกสารนี้ขัดกับ spec.md หรือ plan.md ให้ **เอกสารนี้ชนะ** แล้วแก้ไฟล์ที่ตามมา ห้ามแก้ spec.md ก่อน
- ข้อความ requirement ที่ "ยอมรับแล้ว" คัดจาก `docs/srs/srs.md` v5 **ตรงตัว** ห้ามเติมความหมายเพิ่ม
- สิ่งที่ SRS ไม่ได้กำหนด เขียนเป็น "คำถามเปิด" ไม่ใช่ข้อกำหนด (AGENTS.md ข้อ 2, 3, 5)
- ใช้ ID เดิมจาก SRS ทุกตัว ID ใหม่ที่สร้างได้มีเพียง **AC-\*** ซึ่งอ้างถึง requirement ที่พิสูจน์ (ตามเกณฑ์วิชา Week 04) ส่วนคำถามใหม่ยังไม่มีเลข Q (รอทีมกำหนด ดู §8)
- **AC** ทั้งหมดเป็น **ร่าง รอทีมยืนยัน** เขียนเป็น Given-When-Then 1 พฤติกรรมต่อ 1 ข้อ และไม่เพิ่ม requirement ใหม่ ตัวเลข/เวลาใน AC เป็นข้อมูลทดสอบ ไม่ใช่ข้อกำหนด
- **Status:** "Draft v1" เพราะยังไม่ได้รัน `/clarify` (ตามวิชา v2 เกิดจากผลของ `/clarify`)
- **Assumptions (ASM):** ไม่มี — ทีมยังไม่ได้ตัดสินใจล่วงหน้าในเรื่องใด ค่า "จะเดาว่า" ใน SRS §8.2 ไม่ใช่การตัดสินใจของทีม ยกเว้น **ฟีเจอร์ 001 ที่ผ่าน /clarify แล้วและมี ASM-01..08** (ดู §3.1)

## 3. Feature Specs

> รายละเอียดฉบับเต็มของแต่ละฟีเจอร์อยู่ใน `specs/00N-*/spec.md` ซึ่งต้องตรงกับหัวข้อนี้ (ดู §8 ข้อ 12 เรื่องความซ้ำซ้อน)

### 3.1 Feature 001 — auth-session
**Goal:** สมาชิกที่เข้าสู่ระบบแล้ว กลับมาใช้เว็บอีกครั้งภายในอายุ Session แล้วใช้งานต่อได้ทันทีโดยไม่ต้องเข้าสู่ระบบใหม่ ระบบรักษา Session ด้วย Refresh Token ผ่าน Redis
**Status:** Draft v2 (ผ่าน /clarify 2 รอบ ล่าสุด 8 พฤศจิกายน 2569) — ASM-01..06 ทีมยืนยันรายข้อแล้ว, ASM-09 ทีมเลือกจากตัวเลือก, ASM-07..08 ยังไม่ได้ถามรายข้อ ทั้งหมดเป็นสมมติฐานของทีม
**Out of scope ข้างเคียง:** ลงทะเบียน/ตั้งรหัสผ่านเริ่มต้น (Q-03), ออกจากระบบ/เพิกถอน token (ASM-03, Q-02), เข้าสู่ระบบของเจ้าหน้าที่/ผู้จัดการ, Push Notification, การผูกบัญชี LINE
**Preconditions:** สมาชิกมีบัญชีและรหัสผ่านอยู่ในระบบแล้ว (ที่มายังไม่กำหนด ดู Q-03)
**Constraints:** CON-CACHE-01, CON-DB-01, CON-TECH-01, CON-TECH-02

| ID | Requirement (SRS §3.1 / §4.1) |
|---|---|
| FR-AUTH-01 | **รักษา Session Login แบบ Persistent**: รองรับการเข้าสู่ระบบของสมาชิกและรักษา Session ด้วย Refresh Token เพื่อป้องกันการถูก Auto-logout บ่อยครั้ง |
| NFR-REL-01 | Session Persistence & Reliability: การจัดการ Session ผ่าน Redis ร่วมกับ Refresh Token ต้องมีอัตราการหลุดโดยไม่ตั้งใจไม่เกินเกณฑ์ — อายุ Session และอัตราหลุดสูงสุด = **TBD** (Q2; ตัวเลขอัตราหลุด ดู Q-01) (ไม่มี AC จนกว่ามีตัวเลข อายุ Session ใช้ ASM-02 ชั่วคราว) |

**AC (ร่าง)**
- [ ] **AC-AUTH-01** (FR-AUTH-01, ASM-01) **Given** สมาชิกที่มีบัญชีในระบบและกรอกรหัสนักศึกษากับรหัสผ่านถูกต้อง **When** เข้าสู่ระบบ **Then** ระบบส่ง Refresh Token กลับให้สมาชิก
- [ ] **AC-AUTH-02** (FR-AUTH-01, ASM-02) **Given** สมาชิกมี Refresh Token ที่ออกมาไม่เกิน 7 วัน **When** ขอใช้งานต่อด้วย Refresh Token นั้น **Then** ระบบยืนยันสมาชิกสำเร็จ และสมาชิกเรียกฟังก์ชันที่ต้องเข้าสู่ระบบได้โดยไม่ต้องกรอกรหัสนักศึกษาและรหัสผ่านใหม่
- [ ] **AC-AUTH-03** (FR-AUTH-01, ASM-02) **Given** Refresh Token ที่ออกมาเกิน 7 วันแล้ว **When** ขอใช้งานต่อด้วย Refresh Token นั้น **Then** ระบบปฏิเสธคำขอ
- [ ] **AC-AUTH-04** (FR-AUTH-01) **Given** Refresh Token ที่ไม่ใช่ของระบบหรือถูกแก้ไข **When** ขอใช้งานต่อด้วย Refresh Token นั้น **Then** ระบบปฏิเสธคำขอ
- [ ] **AC-AUTH-05** (CON-CACHE-01) **Given** สมาชิกเข้าสู่ระบบสำเร็จ **When** ตรวจ Redis ด้วย integration test **Then** พบรายการ Session ของสมาชิกนั้นใน Redis
- [ ] **AC-AUTH-06** (FR-AUTH-01, ASM-06) **Given** รหัสนักศึกษาที่ไม่มีในระบบ หรือรหัสผ่านที่ไม่ถูกต้อง **When** เข้าสู่ระบบ **Then** ระบบปฏิเสธ ไม่ส่ง Refresh Token และข้อความไม่บอกว่าผิดที่รหัสนักศึกษาหรือรหัสผ่าน
- [ ] **AC-AUTH-07** (CON-CACHE-01, ASM-05) **Given** Redis ไม่ตอบสนอง (เกิน 5 วินาที ตาม ASM-09) **When** สมาชิกขอใช้งานต่อด้วย Refresh Token ที่ถูกต้อง **Then** ระบบปฏิเสธและแจ้งให้ลองใหม่
- [ ] **AC-AUTH-08** (CON-DB-01, ASM-05) **Given** PostgreSQL ไม่ตอบสนอง (เกิน 5 วินาที ตาม ASM-09) **When** สมาชิกเข้าสู่ระบบ **Then** ระบบปฏิเสธและแจ้งให้ลองใหม่
- [ ] **AC-AUTH-09** (FR-AUTH-01, ASM-04) **Given** สมาชิกเข้าสู่ระบบแล้วบนอุปกรณ์ A **When** เข้าสู่ระบบบนอุปกรณ์ B **Then** Refresh Token ของอุปกรณ์ A ยังใช้ขอใช้งานต่อได้
- [ ] **AC-AUTH-10** (FR-AUTH-01, ASM-07) **Given** สมาชิกเข้าสู่ระบบบนเว็บแล้วภายในอายุ Session **When** ปิดเบราว์เซอร์แล้วเปิดเว็บใหม่ **Then** สมาชิกใช้งานต่อได้โดยไม่ต้องเข้าสู่ระบบใหม่

### 3.3 Feature 005 — class-booking

**Constraints:** CON-DB-01, DOM-BKG-01, CON-TECH-01, CON-TECH-02

|---|---|
| FR-BKG-01 | **จองคลาสออกกำลังกายออนไลน์**: สมาชิกเลือกและจองคลาสที่เปิดรับผ่านระบบออนไลน์ได้ |

| NFR-PERF-01 | Real-time Booking Concurrency: การตรวจสอบคิวว่างและการบล็อกคิวเทรนเนอร์ต้องประมวลผลทันทีเพื่อป้องกันการจองซ้อน — Latency = **TBD** (ไม่มี AC เชิงเวลา) |

- [ ] **AC-BKG-04** (FR-BKG-02, DOM-BKG-01) **Given** เทรนเนอร์มีกะ 09:00–12:00 **When** สมาชิกจองคลาสที่เริ่ม 11:30 และจบ 12:30 **Then** ระบบบล็อกการจอง
