**ปัญหาปัจจุบัน (Pain points)**

1. ลงทะเบียนเข้าใช้ยิมด้วยการเขียนลงกระดาษ บางคนลืมปากกา และบางช่วงมีคิวยาว 7–8 คน
2. ผู้ใช้โดน Auto-logout จากแอปบ่อย
3. นับจำนวนผู้ใช้บริการด้วยการคีย์ Excel
4. เครื่องเล่นที่ตั้งใจจะใช้มักมีคนใช้งานอยู่ (ผู้ให้ข้อมูลไม่เห็นด้วยกับการแก้ด้วยระบบเช็กสถานะเครื่องล่วงหน้า ดูหัวข้อ 2.2)
5. ติดตามข่าวสารและวันปิดปรับปรุงผ่าน Facebook Page เป็นหลัก

## 2. ขอบเขต

### 2.1 ขอบเขตที่ตัดออกตามการตัดสินใจเดิมของทีม

1. **POS และการขายสินค้าหน้าร้าน:** เครื่อง POS / Smart Counter Terminal การบันทึกยอดขาย และการดึงยอดขายไปแสดงบน BI Dashboard
2. **เครื่องสแกนเวลาและการเชื่อมต่อ HR:** การสแกนเวลาเข้า-ออกงานของพนักงาน และการซิงค์เข้าระบบ HR
3. **Data Privacy & Encryption:** ข้อกำหนด TLS 1.3 / AES-256 และ PDPA Compliance
4. **Nutrition:** FR-NUT-01 ฟังก์ชันคำนวณโภชนาการ และ IF-NUT-01 การเชื่อมต่อ Nutrition API ภายนอก

### 2.2 ขอบเขตที่ตัดออกจากความเห็นของผู้ให้ข้อมูล

| รายการ | เหตุผล | สถานะ |
|---|---|---|
| ระบบเช็กสถานะเครื่องเล่นล่วงหน้า / ระบบคิวเครื่องเล่น | ผู้ให้ข้อมูลยังไม่เห็นด้วย เพราะถ้าคนเห็นว่าคิวยาว ระบบคิวอาจจัดการได้ยากในทางปฏิบัติ | ปัญหาการรอคิวเครื่องเล่นยังไม่มีทางแก้ที่ตกลงกัน ส่งต่อเป็น Q10 |

### 2.3 ความต้องการที่ไม่ใช่ซอฟต์แวร์ (บันทึกเพื่อส่งต่อ ไม่พัฒนาในระบบ)

| ลำดับ | ข้อความจากเอกสารต้นทาง | ประเภท | หมายเหตุ |
|---|---|---|---|
| NS-1 | อุปกรณ์มีคุณภาพดี หลากหลาย และ**ต้องการให้เพิ่มอุปกรณ์ออกกำลังกายประเภทใหม่** | การจัดซื้อ / บริหารสถานที่ | ข้อเสนอต่อฝ่ายจัดซื้อ ไม่ใช่ฟังก์ชันของระบบ |
| NS-2 | แอร์เย็น อุณหภูมิเหมาะสมต่อการออกกำลังกาย | สภาพแวดล้อม (คำชมสภาพปัจจุบัน) | ไม่ใช่ความต้องการใหม่ ควรรักษาไว้ |

> NS-x เป็นเลขลำดับของบันทึก ไม่ใช่ requirement ID

## 3. Functional Requirements (FR)

### 3.1 ที่ยอมรับแล้ว

| ID | ความต้องการ | คำอธิบายพฤติกรรม |
|---|---|---|
| FR-AUTH-01 | รักษา Session Login แบบ Persistent | รองรับการเข้าสู่ระบบของสมาชิกและรักษา Session ด้วย Refresh Token เพื่อป้องกันการถูก Auto-logout บ่อยครั้ง |
| FR-NOTI-01 | ส่ง Push Notification | ส่งข้อความแจ้งเตือนวันและเวลาเปิด-ปิดยิม รวมถึงข่าวสารประชาสัมพันธ์ไปยังแอปของสมาชิก |
| FR-LINE-01 | LINE Bot ดึงข้อมูลการจองคลาส | สมาชิกเรียกดูข้อมูลและสถานะการจองคลาสของตนเองผ่าน LINE Bot ได้ |
| FR-LINE-02 | LINE Bot ตอบคำถามเบื้องต้น (FAQ) | ระบบตอบคำถามทั่วไปที่พบบ่อยเกี่ยวกับยิมและการใช้งานผ่าน LINE Bot อัตโนมัติ |
| FR-ROST-01 | จัดการตารางงานเทรนเนอร์ (Trainer Roster) | เจ้าหน้าที่/ผู้จัดการจัด กำหนด และปรับปรุงตารางเวลาเข้างานและเวลาสอนของเทรนเนอร์แต่ละคนได้ |
| FR-BKG-01 | จองคลาสออกกำลังกายออนไลน์ | สมาชิกเลือกและจองคลาสที่เปิดรับผ่านระบบออนไลน์ได้ |
| FR-BKG-02 | บล็อกคิวอัตโนมัติเมื่อเทรนเนอร์ไม่ว่าง | ระบบตรวจสอบและบล็อกการจองซ้อนทันทีเมื่อเทรนเนอร์ติดสอนคลาสอื่นหรือไม่อยู่ในเวลาปฏิบัติงาน |
| FR-INV-01 | จัดการรายการพัสดุและอุปกรณ์ (Inventory Catalog) | เจ้าหน้าที่เพิ่ม แก้ไข ลบ ค้นหา และตรวจสอบจำนวนคงเหลือของอุปกรณ์และพัสดุได้ |
| FR-INV-02 | บันทึกการเบิกจ่ายและรับคืน (Stock Movement) | บันทึกประวัติการเบิกใช้วัสดุสิ้นเปลือง การยืม-คืนอุปกรณ์ และการรับของใหม่เข้าสต็อก |
| FR-INV-03 | แจ้งเตือนสต็อกขั้นต่ำ (Low Stock Alert) | แจ้งเตือนเจ้าหน้าที่เมื่อจำนวนคงเหลือลดถึงจุดสั่งซื้อขั้นต่ำ (Reorder Point) |
| FR-BI-01 | BI Dashboard แสดงจำนวนผู้ใช้บริการปัจจุบัน | ดึงข้อมูลการผ่านประตูทางเข้ายิมมาประมวลผลและแสดงจำนวนผู้ใช้บริการภายในยิมแบบทันที แทนการคีย์ Excel |

## ภาคผนวก ก: ข้อเสนอการลงทะเบียนเข้าใช้ยิม

> **สถานะ: ข้อเสนอ ยังไม่ได้รับการยืนยัน**
> เนื้อหาในภาคผนวกนี้ยังไม่ใช่ requirement ไม่มี ID ที่ยอมรับแล้ว ไม่มี spec, plan, tasks หรือ AC และไม่อยู่ใน `specs/`
> จะย้ายเข้า `specs/` เป็น feature ใหม่ก็ต่อเมื่อทีมยืนยันและตอบ Q6, Q7, Q8, Q11, Q12 แล้ว

**ที่มา**

- Pain point 1 (หัวข้อ 1): ลงทะเบียนด้วยการเขียนลงกระดาษ ลืมปากกา และบางช่วงมีคิวยาว 7–8 คน
- Main Prior REQ ข้อ 1 (draft เดิม): ลงทะเบียนผ่าน QR Code หรือออนไลน์ล่วงหน้า ข้อมูลที่ใช้มีเพียงรหัสนักศึกษาและชื่อ-นามสกุล

**ข้อเสนอและคำถามที่ต้องตอบก่อนยืนยัน**
